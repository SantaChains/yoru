# 04 执行引擎（设计4 + 设计11 opcode 编码 + 设计12 字节码格式）

[上一章：03 类型系统](03-类型系统.md) | [目录](README.md) | [下一章：05 后端取舍](05-后端取舍.md)

## 4.1 执行模型决策（已确认）

栈式字节码 + 解释器（Lua/QuickJS 验证路径）。理由：生成简单、字节码紧凑、热重载以字节码为权威格式；未来 AOT/JIT 通过字节码→SSA 提升接入，前端无需重写。

工程参考（QuickJS 验证）：编译期计算每函数最大栈深，运行时无栈溢出检查；闭包变量访问优化到接近局部变量；压缩行号表承载调试信息。

## 4.2 值表示

MVP：Rust tagged enum——Int(i64)/Float(f64)/Bool/Unit/Nil/String/List/Map/Struct/Closure/HostRef。理由：正确性与可调试性优先。

性能方向（P2，与 JIT 同批）：64 位 NaN-boxing 或低位 tag；热操作必须内联进 IR，禁止 opaque runtime helper 调用（Perry 迁移案例实证：优化边界比优化器质量更重要，method_calls 因 helper 墙慢 68 倍）。

## 4.3 指令集分类（MVP 覆盖）

- 常量与构造：Const/True/False/Nil/NewList/NewMap/NewStruct/NewClosure
- 变量与闭包：LoadLocal/StoreLocal/LoadUpvalue/StoreUpvalue/LoadImport
- 运算：Add/Sub/Mul/Div/Mod/Neg/Not/BitAnd/BitOr/BitXor/Shl/Shr/UShr
- 比较：Eq/Ne/Lt/Le/Gt/Ge（短路逻辑由 Jump 组合）
- 对象：GetField/SetField/GetIndex/SetIndex
- 控制流：Jump/JumpIfFalse/JumpIfTrue
- 调用：Call/CallMethod/Return/TailCall（P1）
- Option/Result：IsNone/Unwrap（编译器在非空路径生成；擦除策略下 Option 展开为 tagged 值）
- 异步：Suspend/Resume（桥接宿主运行时；MVP 仅语法支持 async，执行经宿主）
- FFI：CallHost（带宿主函数签名，类型检查时校验）
- 错误：Raise（除零、越界等运行时错误；Result 是普通值，不依赖异常机制）

## 4.4 设计11：opcode 编码（定稿，栈式字节码）

指令统一 32 位：`opcode(8) | 操作数(24)`。操作数按指令类型解释，三种形态：

| 形态 | 布局 | 适用 |
|---|---|---|
| O（无操作数） | op(8) \| 0(24) | 运算、常量、Return 等 |
| A（无符号 24 位） | op(8) \| u24 | 局部变量索引、常量池序号、函数原型索引 |
| sA（有符号 24 位） | op(8) \| i24 | 跳转偏移（相对当前指令） |

栈式语义：运算指令无操作数（弹 2 压 1）；变量访问经 LoadLocal n / StoreLocal n（n 为当前帧局部槽索引）。P1 寄存器式改造时引入多格式位域（Lua 5.4 iABC 风格），字节码文件格式版本化兼容（4.6）。

### opcode 编号表（16 组 × 16 位，留扩展位）

| 区间 | 指令 |
|---|---|
| 0x00-0x0F 常量/构造 | 0x00 CONST(A) 0x01 NIL 0x02 TRUE 0x03 FALSE 0x04 NEWLIST 0x05 NEWMAP 0x06 NEWSTRUCT 0x07 NEWCLOSURE(A) |
| 0x10-0x1F 变量/闭包 | 0x10 LOADLOCAL(A) 0x11 STORELOCAL(A) 0x12 LOADUPVALUE(A) 0x13 STOREUPVALUE(A) 0x14 LOADIMPORT(A) |
| 0x20-0x2F 运算 | 0x20 ADD 0x21 SUB 0x22 MUL 0x23 DIV 0x24 MOD 0x25 NEG 0x26 NOT 0x27 BAND 0x28 BOR 0x29 BXOR 0x2A SHL 0x2B SHR 0x2C USHR |
| 0x30-0x3F 比较/控制 | 0x30 EQ 0x31 NE 0x32 LT 0x33 LE 0x34 GT 0x35 GE 0x36 JMP(sA) 0x37 JMPIF(sA) 0x38 JMPIFNOT(sA) |
| 0x40-0x4F 对象 | 0x40 GETFIELD(A) 0x41 SETFIELD(A) 0x42 GETINDEX 0x43 SETINDEX |
| 0x50-0x5F 调用 | 0x50 CALL(A) 0x51 CALLMETHOD(A) 0x52 RETURN 0x53 TAILCALL(A)(P1) |
| 0x60-0x6F Option/异步/FFI/错误 | 0x60 ISNONE 0x61 UNWRAP 0x62 SUSPEND 0x63 RESUME 0x64 CALLHOST(A) 0x65 RAISE |
| 0x70-0x7F | 保留（32 个扩展位） |

编码要点：
- CONST(A)：A 为常量池序号（int/float/string/函数原型索引）。
- CALL(A)：A 为实参个数（函数与参数先入栈，Call 弹出 n+1 压 1 结果）。
- GETFIELD(A)：A 为结构体字段序号（编译期解析，字段序号经类型检查确定——结构体形状固定，此为 PIC 免维护的结构性优势）。
- 跳转相对当前指令偏移，编译器负责计算（后端无关）。

## 4.5 设计12：字节码文件格式（定稿）

模块 = 文件头 + 段表 + 校验和。固定 little-endian（[05-后端取舍](05-后端取舍.md) 数值语义承诺）。

```
文件头（12 字节）
  magic     : u32 = 0x4C_4243_30 ("LBC0")
  version   : u16 = major(1) << 8 | minor(0)
  flags     : u16（bit0=含调试段，bit1=段表含校验和）
段表（每段 8 字节：offset u32 | len u32，共 4 段 = 32 字节）
  seg_const  常量池段
  seg_proto  原型段
  seg_debug  调试段（可选，flags.bit0）
  seg_string 字符串表段
校验和：CRC32 u32，覆盖文件头之后全部字节（加载时验证）
```

- 常量池段：`type_tag u8 | 负载`——int(i64)/float(f64)/string(字符串表索引)/proto(原型索引)。
- 原型段：函数原型——参数数 u8、局部槽数 u16、最大栈深 u16、指令流（u32 × n）、upvalue 描述符表（每项：is_local u8 + 索引 u16）、常量池引用表。
- 调试段（可选）：行号表（delta 编码压缩）、局部变量名表（字符串表索引）。
- 校验和强制：加载时 CRC32 验证失败即拒绝加载（支撑 [10-抗冲击测试体系](10-抗冲击测试体系.md) 损坏注入测试）。

**阶段 2 实现细化（2026-10-12，`yoru-bytecode` 落地时回写；文件头补 4 字节保留位凑足定额 12 字节）**：
- **常量池段头部 = 模块级声明表**：`u32 import_count` + import 表（字符串索引）→ `u32 tag_count` + tag 表（名 + 每变体载荷标志，载荷标志决定 TagNew 栈效应）→ `u32 struct_count` + struct 表（名 + 字段名表）→ `u32 field_count` + 全局字段名表（GETFIELD/SETFIELD 的界，阶段 2 = 全局字段名序号）→ `u32 const_count` + 常量记录；
- **常量记录 type_tag**：0=Int(i64) 1=Float(f64) 2=Str(串表索引) 3=Proto(原型索引) 4=Variant(tag 序号+变体序号) 5=Bool(u8)；
- **原型段每项**：params u8 / locals u16 / max_stack u16 / instr_count u32 + 指令流 / upvalue_count u16 + 描述符表 / const_ref_count u32 + 引用表（变长结构显式计数前缀，无 panic 解码的前提）；
- **0x70-0x7B 阶段 2 扩展 opcode**：TOSTRING/FORPREP/FORNEXT/ISTAG/PAYLOAD/ISERR/AWAIT/CONVERT/POP/TAGNEW/NEWRANGE/SLICE（FORNEXT 压 bool 的固定栈效应设计，消除动态栈深验证）；正式化随阶段 3 VM 定稿一并回写本表；
- **验证器分支深度一致性**：摘要解释器要求跳转汇合点深度一致、全程非负、无不可达指令（canonical：lowering 不产死码）——决策 9 第 3 项的强化实现。

可持久化缓存（qjsc 模式）与热重载均以本格式为权威格式。版本不兼容时加载器报结构化错误。

## 4.6 GC 与内存

MVP：引用计数为主。值语义下循环引用基本不可达（struct 拷贝、无共享引用），规避引用计数+循环回收复杂度；确定性释放利于热重载。

资源限制（每 VM 实例独立堆）：内存上限（QuickJS JS_SetMemoryLimit 模式）；执行超时用指令计数/宿主中断回调（JS_SetInterruptHandler 模式）；调用栈深上限。

未来方向：区域释放（模块卸载整片释放）P2；Perceus 风格编译期拷贝消除 P2（见 [09-学习借鉴](09-学习借鉴.md)）。

## 4.7 热重载

模块粒度字节码替换。重载语义：丢弃旧模块顶层状态，重新执行模块顶层（Lua require 语义）。值语义保证无共享可变状态残留，替换安全。宿主可注册状态迁移钩子（P1，Erlang 代码热替换借鉴）。

## 4.8 与实现的关系

opcode 表与文件格式为实现阶段权威输入，对应 [12-实现工作台](12-实现工作台.md) T0.4/T0.5。指令编码任何修改必须走版本升级，禁止无声破坏（字节码为权威格式承诺）。

## 4.9 T1 VM 实现注记（2026-10-12，`yoru-vm`）

- **两层结构（决策 69）**：`Vm`（limits/中断钩子/stats/输出缓冲，跨执行复用）+ `Instance`（模块字节码 + 调试段 + 宿主注册表）。`Vm::run(inst, entry, args)` / `run_at(inst, proto_idx, args)`（strip 产物无调试段时按原型序号直入）。
- **值模型**：Int/Float/Bool/Nil/Str(Rc<str>)/List/Map(Rc<RefCell<Vec<(K,V)>>>)，Struct/Variant/Closure 带 Rc；COW：引用计数==1 原地写，否则克隆（决策 13）。`deep_eq` 值相等，Rc 指针短路。
- **调用**：帧栈 `max_call_depth` 限深；捕获链 resolve_capture 与发射端逐条对齐；内建经统一注册表按名分派。
- **错误**：`VmError::{Runtime(Y-R*)/Limit(Y-L*)/Interrupted}`；Runtime 带 proto/pc/源偏移（决策 70 回溯）；错误码域 Y-R9000 入口缺失、9001 溢出、9002 参数数、9005 assert、9007 类型、9021 内建。
- **资源三限（决策 71）**：max_heap_bytes / max_instructions / max_call_depth + `check_interval`（默认 10_000，QuickJS 节流经验）节流检查 deadline 与中断钩子；触发返回结构化错误而非 panic。
- **观测（决策 72）**：`stats()` 快照（指令数/调用数/堆字节/输出字节）；中断钩子 `Box<dyn FnMut(&Stats) -> bool>`。
- **差分一致性（22 号约束 6）**：同一源码 debug 与 strip 产物执行结果 + 输出深相等（测试锁定）；strip_assert_is_noop 锁定决策 70。
- **实现期抓出的关键缺陷（测试锁定）**：lowering 死码消除的「最后一条指令是 Return」启发式在 `if c { return }` 循环体上**误删回跳 → 循环只跑一轮**，已替换为 AST 级全路径收束分析；`xs |> map(f)` Call 参数计数漏 lhs（验证器盲区：只查栈深不查语义参数）。
