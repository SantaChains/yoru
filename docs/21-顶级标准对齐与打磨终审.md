## 3. 文档体系对齐 Diátaxis（决策 64）

Diátaxis（Django 核心开发者 Procida 提出，2025 年事实标准）的四象限按**用户意图**组织文档：学习（Tutorial）/ 应用（How-to）/ 查询（Reference）/ 理解（Explanation）。Yoru 现有 21 份文档的病理正是 Diátaxis 描述的「content chaos」——设计与规范混编、无学习路径。

**四象限规划**（v0.1 发布前建成，AI 消费者同样受益——结构化意图 = 更准确的检索与生成）：

| 象限 | Yoru 内容 | 来源 |
|---|---|---|
| **Tutorial**（学习向，可重复、必成功） | 「5 分钟写第一个 Yoru 插件」「宿主嵌入 10 分钟上手」 | 新写；以权威样例（19.5）为骨架 |
| **How-to**（任务向，只写动作） | 「如何注册宿主能力」「如何调试 Y-R 运行时错误」「如何用 yoru fix 自动修复」「如何迁移 X.Y 版本」 | 新写；从 20 号 §2/§3 派生 |
| **Reference**（事实向，无论述） | 19 号语法规范、错误码站（Y-xxxx 长文）、stdlib API、CLI 手册、LBC0 格式 | 现有文档拆出规范部分 |
| **Explanation**（理解向，讲 why） | 现有 01-20 全部设计文档归位于此 | 归位即可 |

**防类型漂移**（Diátaxis 头号陷阱）：每篇文档头部声明象限标签；Reference 页禁 advice、How-to 页禁理论——越界内容移到对应象限并交叉链接。「文档即 AI prompt 资产」的三份产物（词汇表/存根/文档）保持 14 号不变，Diátaxis 结构让它更可检索。

## 4. CLI 交互契约（决策 65，阶段 5 落地）

clig.dev（Docker Compose 作者等合著的 CLI 设计权威指南）核心契约投影到 `yoru` CLI：

1. **流分离**：主输出→stdout；诊断/进度/警告→stderr；机器输出（`--json`）→stdout 且**完整、确定、无人类散文混杂**；
2. **exit code 契约**（自动化刚需，小而稳定）：`0`=成功、`1`=一般运行失败、`2`=用法/输入错误；禁止对预期用户错误 panic；
3. **颜色**：尊重 `NO_COLOR` 与非 TTY；`--color auto|always|never`；
4. **子命令动词化**：`yoru check | fix | fmt | build | run | test | doc`——名字即动词，与 clig「命令即动词」一致；
5. **verbosity 阶梯**：默认安静、`-v` 要点、`-vv` 详尽、`-q` 抑制非必要输出；
6. **补全与手册**：shell 补全（bash/zsh/fish）与 man 页随发行包交付；
7. **破坏性操作**：`fmt`/`fix` 支持 `--diff` 预览（与决策 59 的「L3 永远 diff 输出」同源）。

**测试**：CLI 契约用 `assert_cmd`/`trycmd` 转录测试——help 示例、exit code、stdout/stderr 分离全部有快照（防止「help 里的示例跑不通」这类腐化）。

## 5. REPL 规范（决策 66，补入阶段 5 交付物）

多项语言实现（含 Rust 生态标准做法）验证的 REPL 必备面，Yoru 全收：

- **多行输入**：括号平衡验证器（Incomplete → 续行提示 `... `）——与 Yoru 换行终止语法天然匹配：**新行不完整时继续，完整即执行**，比 Lua/Python 的显式续行符更顺；
- **历史持久化**：跨会话保存（rustyline 多行感知历史 V2 格式）；
- **表达式自动打印**：最后表达式的值自动显示（REPL 特权，脚本模式不打印——WFL 等实现的标准二分）；
- **`:` 命令面**：`:help :quit :clear :history :type :dump-ast`——冒号前缀避免与 Yoru 标识符冲突；
- **防挂**：每次执行继承 60s 超时（可配）——REPL 死循环不该锁死终端；
- **错误恢复**：出错打印诊断后继续循环（与脚本模式 fail-fast 相反——两种入口两种失败哲学，文档写明）。

**与值语义的互动红利**：REPL 状态即普通绑定，`:clear` = 重置绑定表，无隐藏状态可泄漏——比 ML 系 REPL 的可变全局环境干净。

## 6. 发布工程（决策 67）

Rust release train 六周节奏 + edition 机制是语言演进工程的标杆，Yoru 取**最小可用投影**（单维护者阶段不学六周火车）：

1. **纪元即 Edition**：16.4 T1 的「语言纪元」绑定 Rust Edition 模式——破坏性变更打包进新纪元、旧纪元代码永久可编译（纪元间由迁移工具 `yoru migrate` 桥接）；
2. **semver + MSRV 声明**：`Cargo.toml` 写 `rust-version`；MSRV 提升算 minor；pre-1.0 期明示「minor 可能含破坏性变更」；
3. **发布渠道两档**：dev（git main，不稳定，特性门控）/ stable（tag 发布，冻结层承诺生效）；**不设 nightly**——单维护者养不起三渠道，dev 即 nightly；
4. **发行物**：cargo-dist 生成跨平台二进制 + shell 补全 + man 页；`Cargo.lock` 随应用二进制提交；
5. **变更纪律**：CHANGELOG 面向用户；冻结层（17 号）变更必须走决策记录 + 纪元；
6. **安全发布**：漏洞先补丁后披露；严重损坏版本 yank；advisory 走 SECURITY.md 通道。
