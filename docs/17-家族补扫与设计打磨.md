## 17.0 决策速览（本轮新增）

| # | 决策 | 内容 | 依据 |
|---|---|---|---|
| 40 | 流敏感智能收窄 | `if best != nil { ... }` 分支内 `best` 自动收窄为 `T`；tag union `match` 分支内自动绑定载荷。收窄因**重新赋值失效**；闭包按值快照（决策 31）保证无别名失效。`!` 保留为收窄不可用时的显式逃生 | TS 收窄 + Kotlin smart casts 双先验（语料最密）；值语义 + 闭包快照使 flow analysis sound 且实现极简（只追踪局部变量）；消灭 AI 最高频的「忘解包」错误类，`!` 从日常操作降级为逃生舱 |
| 41 | 函数式字段更新 | 派生新值用 `Entry { ..base, title: t }`（Rust 结构体更新语法先验）；owned `let mut` 局部 struct 允许字段直接赋值 `e.size = 5` | 补 15 号硬缺口（value semantics 下「改一个字段」此前无形式）；Kotlin data class `copy()` 证明派生更新是高频刚需；`..` 单一形式，无二义 |
| 42 | 切片唯一形式 | `xs[a..b]` 半开区间（含头不含尾）**唯一**切片形式；**禁负索引**；无 `..=`（不引入双区间算符）；越界 = 运行时错误 | Rust `..` vs `..=` 双形式是 AI 高频错误源；Python 负索引是隐式行为（违反语义可局部判定）；半开区间与 for-in/len 约定自洽 |
| 43 | 未使用符号 = 警告 | 未使用 import / 未使用局部变量 = typeck **警告**（非错误） | Go 定为 error 但 Go 场景无 AI 迭代循环；AI 生成-修复循环中 error 会阻塞在「删一行」这种琐事上；警告进诊断 JSON，formatter/审稿闭环可见，不阻塞编译快 |

## 17.1 五语言补扫：取 / 砍 / 验证

### Go

| 项 | 处置 | 说明 |
|---|---|---|
| gofmt 唯一格式 | **验证 T3**（16.4 canonical formatter） | Go 证明「格式不由讨论」是规模化可读性的地基——正是规范形式的运行时保障 |
| 「一种显而易见的写法」 | **验证规范形式** | Go 无继承/无重载/无异常的减法哲学与 Yoru 同源；Go 的成功实证了减法语言在大团队/大时间跨度下的维护优势 |
| 工具链一体（build/fmt/vet/test/doc/mod） | **验证 T5** | 单一二进制工具链降低 AI 调用面复杂度——`l` CLI 应一次成型 |
| 编译快是文法约束（禁循环 import、import 必用） | **取**：import 必用进决策 43；**禁循环 import 直接采纳** | 循环 import 是编译图复杂度之王，Yoru 的模块图从一开始就定死 DAG |
| 未使用变量 = error | **改为警告**（决策 43） | Go 是人类团队场景；AI 修复循环里 error 阻塞在琐事上得不偿失 |
| 隐式 interface | **再验证已砍**（15 号协议显式 impl） | Go 的隐式满足关系不可 grep，与「谁实现了什么必须一眼可见」冲突；consumer-side 小接口思想保留为 Yoru 协议的使用建议而非语言机制 |

### Kotlin

| 项 | 处置 | 说明 |
|---|---|---|
| null safety（`T?` + `!` 双形式） | **验证 + 取 smart cast** | Yoru 的 `T?`/`!` 与 Kotlin 同构（Swift 先验）；本轮补上 Kotlin 的 smart casts（决策 40），`!` 的日常使用率降一个量级 |
| data class `copy()` | **取**（决策 41） | 不可变数据的「改一个字段」是最高频操作之一，必须有一等形式 |
| sealed + exhaustive when | **验证 tag union + match 穷尽** | Kotlin 十年实证「编译器强制穷尽」消灭漏分支错误类 |
| 结构化并发（scope 取消传播） | **维持宿主职责** | Yoru 的 await 只作用于宿主能力（14.5），取消/超时是宿主调度器的事；语言不内建 scope |
| 扩展函数 | **砍** | 向既有类型注入方法破坏「签名即完整契约」（方法来源不再可 grep）；Yoru 用 protocol/impl 表达同等能力 |

### MATLAB

| 项 | 处置 | 说明 |
|---|---|---|
| 「矩阵即一等公民」的教科书感 | **验证协议过载路线** | Yoru 的 Vec3/Mat 协议过载 + stdlib 数学函数即是同一路线：领域数学读起来像教科书 |
| 整体数组运算（vectorized） | **走 stdlib 不走语法** | `map`/`filter`/管道（决策 25）+ 数值函数已是等价物；内建 broadcast 的隐式维度规则是隐藏行为 |
| `.*` vs `*` 双乘法符 | **砍** | MATLAB 为区分逐元素/矩阵乘引入两个乘号——一操作两形式的反面教材；Yoru 的 `*` 语义由类型对应的协议定义，一种形式 |
| 1-based 索引 | **拒绝，维持 0-based** | MATLAB/R 证明 1-based 对数学人群友好，但 AI 先验压倒性 0-based（C/JS/Python/Rust/Go）；先验迁移优先 |
| 演进而非革命（Fortran 同） | **验证 T1 纪元模型** | MATLAB 四十年、Fortran 七十年不死的共同原因：向后兼容纪律——正是 16.4 T1 的证据 |

### Fortran

| 项 | 处置 | 说明 |
|---|---|---|
| 反别名保证 → 极致向量化 | **值语义免费获得更强版本** | Fortran 靠「哑元不别名」假设解锁 SIMD；Yoru 的值语义连别名都不存在，T2 AOT 后端继承同一收益 |
| `pure`/`elemental` 纯度标注 | **验证能力即参数** | Fortran 用标注声明纯度，Yoru 用「签名里没有能力参数」判定纯函数——零标注拿到同一审计收益 |
| 整体数组切片 `A(1:50, 1:50)` | **取切片语法**（决策 42） | 多维数组留 T2+（Yoru 现阶段 `[T]` 一维 + struct 组合）；切片的半开区间形式从 Rust/Go 取 |
| 条件表达式（Fortran 2023 才引入） | **验证已砍三元** | Fortran 坚持六十六年才向三元妥协；if-表达式是更优解，Yoru 起点即终点 |
| Coarray / do concurrent | **不做** | 并行是宿主调度域（同 Kotlin 结构化并发处置）；语言层内建并行模型与「编译快」冲突 |

### R

| 项 | 处置 | 说明 |
|---|---|---|
| 原生管道 `|>`（R 4.1） | **验证决策 25** | 管道记法收敛从五方变六方；且 R 证明管道从包生态反哺进语言核心是自然演进路径 |
| tidyverse「一致动词词表」 | **验证词汇表机械导出** | dplyr 的 filter/select/mutate/group_by 命名一致性是非程序员快速生产力的根因——正是 Yoru 的「签名即词汇表」路线的统计学界实证 |
| 静默类型强转（coercion） | **反面教材** | R 的 `c(1, "a")` 全转字符串、recycling 规则静默复用短向量——正是决策 26（禁隐式转换）要根治的错误类 |
| NA 传播语义 | **拒绝，Option 已覆盖** | R 的 `NA` 参与运算静默传播是可读性陷阱；Yoru 的 `T?` + 显式处理是 canonical form |
| formula DSL（`y ~ x`） | **拒绝** | 语言内嵌 DSL 语法糖破坏规范形式；统计建模不是 Yoru 的域 |
| 双方言分裂（base R vs tidyverse） | **警示** | 同一语言两种习语=认知税；Yoru 的规范形式审计表就是防方言化的制度——这也是为什么「一操作一形式」必须从 day-1 强制 |

## 17.2 宏观打磨：决策链的稳定性分层（长期收益视角）

42 项决策不是同一块石头——按「改动成本」分三层，未来演进时每层纪律不同：

| 层 | 内容 | 演进纪律 |
|---|---|---|
| **冻结层（永不改）** | 值语义、能力即参数、规范形式（一操作一形式）、换行终止、pub 显式导出、深相等、UTF-8 唯一编码、溢出抛错、无宏无类无继承、签名即完整契约 | 改动 = 新语言。任何 RFC 触碰本层默认否决 |
| **演进层（semver 纪元）** | stdlib L1 函数集、协议清单、错误消息 schema、字节码格式（LBC0 版本号字段已预留）、**软类型（Ty::Num/Coll/Any）与未来泛型数值约束的收敛方向**（23 号 D3：union 全面化 or 内建面专用，泛型约束实装时决策）、**`using` 注入式 import**（23 号 J1：阶段 5 评估） | 按 16.4 T1/T2 流程：实验旗标 → 双轨 → 纪元切换 |
| **可选层（随实现裁量）** | T2 Cranelift AOT、TCO、环绕算术变体 `+%`、distinct P1、泛型特化深度、正则宿主注入 | 实现期按 profile 实测决定，不影响前端契约 |

**长期收益的主导逻辑**：Yoru 的复利来自两个正交资产——①**词汇表资产**（签名完备 → 词汇表/文档/兼容检测三份机械产出，随时间只增不减）；②**冻结层承诺**（AI 的先验投资永不作废，类比 Go 十年语法零破坏带来的工具生态复利）。所有「短期看着爽」的加法（宏、隐式转换、dynamic、扩展函数）都在稀释这两项资产，这就是砍它们的宏观理由。

**设计完整度终审结论**：语义层面已无已知空洞——语法（15）、语义（16）、执行（14）、工具链（16.4）、家族证据（13/17）五链闭合。剩余开放项只有两个，均不阻塞实现：①命名（Loam/Ludex/Luxel 候选，crates.io/npm/域名终审后定）；②决策 9-43 的正式登记与编号重排（11 号还停留在 1-8，登记动作与实现并行即可）。
