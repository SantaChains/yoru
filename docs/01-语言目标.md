# 01 语言目标（LDP）

[目录](README.md) | [下一章：02 语法规范](02-语法规范.md)

## 1.1 定位

Yoru 是一门嵌入式沙盒脚本语言：语法表层亲近 TS/Flow 开发者，语义内核采用渐进类型与显式检查，参考 Lua/Luau 的极简与可嵌入设计。

- 宿主无关：语言内核只定义字节码虚拟机、类型系统、FFI 抽象层。任何 Rust 程序可嵌入（Tauri 只是场景之一）；未来通过 C ABI 接入其他宿主。
- 使用场景：插件/扩展脚本、配置逻辑、热重载模块、AI 生成的可执行片段。
- 生态位声明：宿主内脚本层（Lua 生态位），非独立主语言。与 MoonBit 等主语言定位互补，边界论证见 [08-必要实现与生态边界](08-必要实现与生态边界.md)。

## 1.2 设计目标（按优先级）

1. 渐进类型：无标注代码合法可跑（推断为 dynamic），有标注代码获得静态检查；标注不改变运行时语义。
2. 健全性分级：strict 追求类型健全（除显式信任点 `as`/dynamic 边界外，静态通过则运行时类型成立）；nonstrict 仅消除可证明的运行时错误（Luau 路线）。
   **边界声明（27 号 A2）**：健全承诺的适用范围**不含两个显式信任点**——`x as T`（决策 26，无条件信任、运行期可崩，TS 同源 unsoundness）与 dynamic 边界（决策 5，运行期 cast guard）。二者为有意取舍：逃生舱换互操作与渐进迁移能力，代价是「strict 健全」须读作「除显式信任点外健全」。future：可考究「debug 模式下 as 边界插检查」作为折中。
3. 语法极简与熟悉并存：关键字少（Lua 哲学：内核小，能力交给库）；表达式风格贴近 TS。
4. 沙盒安全：默认零权限，无 eval、无动态代码执行、无隐式转换；资源限制内置于虚拟机。
5. 编译与执行速度：MVP 字节码解释器，编译速度优先，支持增量编译（阶段1）。
6. 热重载一等公民：源码→字节码→模块替换，不重启宿主。
7. 人+AI 双端友好：人类可读 + JSON 结构化诊断（机器可定位修复）。
8. 互操作：Rust FFI 第一优先，类型绑定自动生成。
9. 默认局部作用域：所有绑定默认词法局部，无隐式全局；导出必须显式 export。

## 1.3 非目标（明确拒绝）

- 不兼容 TS/JS 生态（不做 JS 运行时超集）。
- 不做通用系统语言（不替代 Rust/Zig）。
- 不做浏览器语言（无 DOM）。
- 不追求极致性能（非 V8；JIT/AOT 为分阶段方向）。
- 不支持多返回值（MVP 用元组）、宏系统、包管理器。

## 1.4 取舍清单

保留（MVP 必须）：let/const、fn、结构体、ADT 枚举、match；默认局部作用域；可选静态类型+推断；Option 空安全；显式转换；import/export；async 语法糖（底层复用宿主运行时）；结构化诊断。

裁剪（永久删除）：原型链、动态对象属性；eval/动态代码执行；隐式类型转换；this 动态绑定；TS 类型级元编程（条件类型等）；any（用 dynamic 替代）；null。

未来方向（MVP 放弃，登记）：JIT、AOT、C ABI 多语言 FFI、完整泛型、宏/包管理/LSP、增量 GC/区域内存。详见 [07-路线图](07-路线图.md)。

## 1.5 设计依据（学术来源）

渐进类型与双模式决策基于已发表研究，非凭空取舍：

- Siek & Taha (2006)：渐进类型奠基，dynamic 与一致性关系 ~。
- Siek et al. (2015)：渐进保证——增删标注不改变程序行为。
- Takikawa et al. (2016)：健全渐进类型运行时开销实测，混合配置可超 10000%——边界策略必须显式选择（决策5）。
- TS 官方立场：放弃健全性换零开销——本项目路线与其不同。
- Luau（HATRA'21/23）：双模式设计（nonstrict 消除误报 / strict 消除漏报）；语义子类型与错误抑制重构；type soundness 证明。
- BNF/EBNF 实践（JLS、Scheme R4RS、BNFC）。

## 1.6 内核与差异化优势

内核三支柱：渐进类型分级 / 值语义+默认局部 / 宿主无关沙盒执行。

| 对比对象 | 差异点 |
|---|---|
| TypeScript/JS | 无历史包袱（无隐式全局/转换/原型链/eval）；strict 全类型化可健全；值语义 |
| Lua/Luau | 修复全局污染（默认局部）；类型系统原生设计（Luau 为后补）；Result；不可变默认 |
| QuickJS | 无 ES/DOM 包袱；类型原生；Rust 原生嵌入（无 C 桥层）；沙盒零权限 |
| Python/Lua 系 | 显式化（分号必写/显式转换/显式可变）降低 AI 生成错误率；JSON 诊断可被 Agent 修复 |

三档执行：字节码（开发/热重载）→ 单层 JIT（热点）→ AOT 双后端（发布），同一字节码权威格式，后端切换不重写前端。领域定向：游戏数学 + 底层运算，切入 Rust 图形栈（wgpu 等）。
