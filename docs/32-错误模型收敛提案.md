## 32.1 现状：三条失败通道并存

| 通道 | 语法 | 语义 | 捕获机制 |
|---|---|---|---|
| `Result<T, E>` | `Ok`/`Err` 构造器、`try` 传播、忽略 = 警告 | 值类型（决策 54/82：可 match，Ok+Err 穷尽） | 手工（match / try 逐层） |
| `T?`（Option） | `nil` 字面量、`!` 强解、`== nil` 收窄 | 值类型（决策 39/40/55） | 手工（nil 检查） |
| `throw` | `throw expr` | **Raise 穿透一切**（26 号 D-21）：try 无捕获机制，宿主边界才可截 | **无**（语言面不可恢复） |

证据（自有文档/示例自证）：19.5 权威示例 `Node(p) -> Ok(try depth(p.left!, d + 1))`——try 传播后须手工包回 `Ok` 才能满足臂类型统一；`if best == nil or it.size > best!.size`——判空守卫自身被迫强解。

## 32.2 问题清单

1. **目标自相矛盾**：「AI 错误少」是第二优先级，但三通道 = AI 出错面 ×3——同一失败语义有三种表达，LLM 风格漂移下必然混用。
2. **throw 不可恢复**：比 Go（有 recover）更激进。宿主可截但语言内不能——库作者写 throw 即断绝调用方恢复权。
3. **try 传播的包回税**：`Ok(try f())` 形态是三通道互不相通的直接产物（Swift 一个 `try` 全解决，Rust 一个 `?`）。
4. **Option 工效空洞联动**：无 `?.`/elvis/if-let（深评 #6），nil 检查退化为 if 链 + `!` 强解——通道 2 自身的工效债。

## 32.3 收敛方案对比

### 方案 A：Swift 式 throws 单通道（推荐）

- **失败 = throw**：`throw` 为唯一失败构造；`try f()` 传播；新增 `catch`（match 式臂，捕获错误值）；函数失败即抛，签名可标 `throws E` 供 typeck 穷尽检查。
- `Result<T, E>` **降级为纯数据类型**（库形态，供显式传递失败值），不再承担传播职责——`try`/`Ok` 包回税消失。
- `T?` 保留（缺失 ≠ 失败，语义上正当），但补齐工效：`?.` 安全调用或 `if let`（二选一，另立决策）。
- **先例**：Swift 全生态验证；错误即控制流与嵌入定位契合（宿主截获点单一）。
- 代价：VM Raise 通道改为可捕获（需栈帧错误表 + catch 展开，工程量中等）；现库内 `Result` 返回的内建需迁移。

### 方案 B：Rust 式 `?` 单通道

- **失败 = Result**：`try` 全权传播（含 Option：`T?` 视作 `Result<T, Unit>` 统一）；**移除 throw**（或 throw = `return Err` 的糖）；忽略 Err = 警告维持。
- **先例**：Rust；错误即值，与「顶层纯声明、显式一切」的纪律最契合。
- 代价：错误路径样板最重（每层显式 `Result` 签名）；throw 现有用法（内建解析失败、溢出等**运行时错误**）须另立不可恢复 panic 通道——**砍不干净**，实际会变成 Result + panic 两通道，收敛度不如方案 A。

### 对照：不收敛（维持现状）

- 三通道 + 无捕获 throw + 包回税永久化。与 AI-first 定位冲突最大，但零迁移成本。

## 32.4 迁移面盘点（方案 A 口径）

| 层 | 影响面 |
|---|---|
| VM | Raise 通道加可捕获展开（catch 表 per proto 栈帧）；`Try` 指令语义扩展 |
| 内建 | 返回 `Result` 的内建（parse_int/get 等）→ 改 throw 或双形态，逐个定夺 |
| typeck | `throws E` 签名检查、catch 臂穷尽性、try 作用域规则 |
| 示例/spec | 19.4 失败行、19.5 示例、stdlib 文档（06 号）全量回写 |
| 兼容 | LBC0 major bump（Raise 语义变更） |

## 32.5 建议

1. **定夺方案 A**（throws 单通道）——与嵌入定位、AI-first、单一恢复点三项最契合；Result 保留为数据类型维持显式传递能力，不回退现有表达力。
2. **分阶段**：① catch + 可捕获 Raise（VM/typeck）→ ② 内建迁移 → ③ Option 工效补齐（`?.` 或 if-let，独立决策）→ ④ spec 全量回写 + LBC0 major。
3. **不动项**：溢出/除零等算术运行时错误维持不可恢复 panic（与失败通道分离——程序 bug ≠ 可预期失败，Rust 同此界）。
