# 14 AI 优先的语言设计与执行模型定稿（优先级重排）

[目录](README.md)

> 状态：调研定稿。承接用户 2026-10-11 第二次方向调整：**从 AI 底层原理、学术界与大厂实践出发，思考 AI 写什么样的语言、配什么类型的检查才不容易弄错；在编译快与运行占用低的前提下确定最合适的执行方式（编译/翻译/虚拟机）；定稿热重载能力与 Rust 交互通道；覆盖基本前端功能；砍掉复杂语法。**
> **优先级重排（本篇的最高约束）：编译快 > AI 错误少 > 热重载 > 其余（安全 / 性能 / JIT / 效率 / 占用）。** 这推翻了 13.0 的向量（安全 > 速度 > 编译快），修订按 11-决策记录流程登记为建议决策 14-18。
> 所有外部数据均已网络核实，来源见 14.9。

## 14.0 优先级重排的连锁反应

三个直接后果，贯穿全篇：

1. **执行模型的天平从「原生编译」倒回「字节码解释」**。T2 加载时 AOT 的主要卖点是峰值性能（13.6 矩阵的 2-4×），而性能已跌出前三；Cranelift 的数 MB 占用与集成复杂度却在消耗「编译快」与「占用」。**T1 寄存器 VM 升格为唯一强制执行层**，T2-T4 降级为可选扩展（建议决策 14）。这不是推翻 13.1 四层模型，是重新排序——四层架构保留，但 T1 是产品，T2+ 是路线图。
2. **「AI 错误少」的主战场不在语法，在「生成→验证→修复」闭环的速度与质量**。学术证据（14.1/14.2）显示语法错误占比最低、API 滥用与逻辑错误占大头——类型检查与运行时兜底只能拦一小部分，**快到毫秒级的机器可读反馈闭环**才是 AI 错误率的一阶变量（RECODE-H：反馈采纳是修复的必经之路）。而闭环速度 = 编译速度，这就是「编译快 > AI 错误少」内在耦合的实证版。
3. **热重载获得结构性简化**。BEAM 双版本机制的复杂度大头是状态迁移（code_change/3）；Yoru 的值语义 + 每次调用全新上下文（插件模型）意味着**没有需要迁移的状态**——热重载退化为「重编译 + 原子换表」，毫秒级且无需任何迁移钩子（建议决策 16）。

## 14.1 AI 为什么写错代码：底层原理与错误分布

LLM 是对训练语料的下一 token 预测器，错误分布由「语料密度 × 语言自由度」两个变量决定，且高度可测量。

### 错误分类学（arXiv 2407.06153，9 个模型 × 4 基准 × 5741 个标注错误）

| 错误大类 | 占比结论 | 细分 |
|---|---|---|
| A 语法错误 | **最少见**（复杂度上升也几乎不涨） | 不完整结构、缩进、导入错误 |
| B 运行时错误 | 中 | **API 滥用是运行时错误最大头**：TypeError 50%、ValueError 26.9%、AttributeError 20.9%；其余为定义缺失、边界检查缺失 |
| C 功能错误 | **最大头**，随任务复杂度上升 | 角落用例检查缺失（HumanEval+ 占 54.4%）、逻辑误解、幻觉 API、I/O 格式错误 |

关键含义：**语法层是 AI 已经基本解决的问题**。一门新语言哪怕 BNF 更简单，在「语法错误少」上的收益也接近于零；收益必须从 B/C 类去挣——而 B 类的根因是「API 属性/参数类型/值域需要同时推断」，C 类的根因是「语言允许多种写法 + 隐式状态管理」。

### 语言选择对 AI 正确率的影响（语料密度效应）

- The Stack 语料量级：JS ~480GB、Python ~190GB、Rust ~40GB。**Rust 是 AI 最难写对的主流语言**：包幻觉率均值 24.74%（三语言最高，且 3 个模型超 40%）；PROBE 基准中 Rust 非编译通过率最高；Acher & Jézéquel (2026) 用 17 种语言国际象棋引擎实测，主流语言强度上限 ~1900-2200 Elo、调试 prompt 占比 <0.2，长尾语言全面劣化且 agent 自评虚高 200-1100 Elo。
- JS 在包幻觉上跨模型最稳定且最低（生态名注册密度最高）。
- **含义（诚实评估）**：Yoru 作为零语料新语言，AI 生成正确率**先验上劣于**任何主流语言。这不是悲观而是路线依据——下节的 Anka 实验给出了唯一被证实的翻盘路径。

### 翻盘路径：Anka 实验约束语法的有效性（arXiv 2512.23214）

核心假设：LLM 在复杂多步任务上的系统性错误源于**通用语言的灵活性**（同一计算多种有效写法 + 隐式状态管理）。Anka DSL 用四条设计原则验证：

1. **规范形式（canonical forms）**：每种操作只允许一种语法（过滤永远 `FILTER source WHERE cond INTO target`），消灭决策点；
2. **中间结果显式命名**：每步 `INTO` 命名输出，杜绝变量遮蔽与状态丢失；
3. **显式分步结构**：编号 STEP 块，防操作排序错误；
4. **冗长关键词代替符号**：利用 LLM 的自然语言强项，避免符号混淆。

结果：Claude 3.5 Haiku **零训练暴露**下 99.9% 解析成功、95.8% 任务准确率；**多步管道任务上比 Python 高 40 个百分点（100% vs 60%）**，GPT-4o-mini 跨模型复验 +26.7pp。配套 Text2DSL（arXiv 2606.22586）：把 **BNF 文法 + API 规格 + 允许的标识符词汇表**注入上下文，句法有效率升至 98.6-99.4%，结构有效率 +9.7~+35.5pp，且跨模型规模稳定。

**这是 Yoru 存在的合法性证明**：为 AI 设计的受约束语言可以胜过 AI 受过海量训练的通用语言——但前提是把 14.7 的规范形式纪律做实，并把「语言规格随宿主分发、直接进 prompt」做成一等交付物。

## 14.2 什么类型的检查最有效（按拦截率 × 成本排序）

| 检查层 | 拦得住什么 | 证据 | 对 Yoru 的成本 |
|---|---|---|---|
| 1. 解析器 | 语法错误 | AI 语法错误本就最少（14.1） | 已有，零增量 |
| 2. 类型检查（strict + 流式收窄） | **B 类主力**：null/undefined 访问、参数类型不匹配——恰是 AI TypeError 集中区 | Gao/Bird/Barr ICSE 2017：TS 可拦截 JS 真实 bug 的 ~15%；Airbnb 迁移分析 38% 生产 bug 可被 TS 预防；strict 模式收益集中在 strictNullChecks | 已定稿（03），流式收窄 P1 维持 |
| 3. **API 面验证（本篇新增）** | **幻觉 API、错拼标识符、越权调用**——B 类最大头 + C 类幻觉 | Rust 幻觉论文：缓解靠 registry 感知校验 + 编辑距离近似名检查 + manifest 交叉核对，prompt 方法收效甚微 | **Yoru 的结构性优势**：API 面全部由宿主注册、可枚举、无全局命名空间——host 可把**精确词汇表**喂给 AI（Text2DSL 证实），typeck 拒绝未注册标识符 |
| 4. 规范形式 lint | 多写法漂移、隐式状态、超长链 | Anka：受约束形式在多步任务 +40pp | 编译器强制，比 lint 更硬 |
| 5. 机器可读诊断闭环 | 一切可检出的错误（修复率的主要变量） | RECODE-H：反馈采纳是修复的必经之路，采纳率随反馈质量单调上升；Acher：agent 自评不可信，外部验证必须 | 12.2 已定义 JSON 诊断——**升格为发布门槛**（建议决策 15）：每条诊断含 span/code/message/suggestion/fix，AI 一轮修复成功率设为可测量指标 |
| 6. 测试 | C 类角落用例/逻辑错误（唯一防线） | 14.1 C 类占比最大且类型系统无法触及 | 插件 scale 下用宿主沙盒跑声明式用例即可 |

结论：对 AI 错误率而言，**「检查的类型」不如「检查的反馈速度与机器可读性」重要**。Google 构建延迟研究（Sadowski et al., IEEE Software 2023）实测**不存在生产力拐点**——编译每快一点，开发者（与 AI agent 的修复循环）都线性受益；人类对等待时间的主观估计严重失真，短的反馈回路直接改变工作方式（Zig 社区「编译器太慢，所以我们才有 bug」）。

## 14.3 执行模型定稿：编译还是翻译，虚拟机还是原生（建议决策 14）

九维在新优先级下重排后，各执行方案的得分：

| 方案 | 编译快 | 占用 | 热重载 | AI 错误少 | 性能 | 结论 |
|---|---|---|---|---|---|---|
| 树遍历解释器 | 最优 | 小 | 最优 | 中性 | 差（~0.1×） | ✗ 性能低一个量级，且 04 已定稿字节码 |
| **源码→字节码（单遍）→ 寄存器 VM** | **最优档**（µs-ms/千行，Pascal 纪律） | **300-500KB 级**（Janet 量级） | **最优档**（重编译=重编译字节码，无 codegen） | ✓（闭环最快） | 基线 1×（Lua 5.4 级） | **✓ 定稿：唯一强制层** |
| T2 加载时 AOT（Cranelift） | 毫秒级/千行（可接受） | +数 MB | 需缓存失效协议 | 中性 | 2-4× | 降级为可选扩展（性能已出前三，不值得为其付出占用+复杂度） |
| T3 优化 JIT | 函数级 | +guard/deopt 基建 | 需失效协议 | 中性 | 3-8× | 维持 P2 以后 |
| T4 LLVM | 秒级 ✗ | 编译期 | ✗ | 中性 | 3-10× | 维持独立工具链 |

**定稿**：Yoru 的执行模型是「**编译为自有字节码（翻译）+ 纯 Rust 寄存器 VM 解释**」。理由链：
1. 新优先级下「编译快」由三层贡献：词法/语法/类型检查（前端，Pascal 单遍纪律已有）、字节码生成（寄存器编码，04 定稿）、**无 codegen**（T2+ 全部砍出强制路径）；
2. 寄存器 VM 的运行时开销对脚本/插件场景足够低（Lua 5.4 证明 1× 基线覆盖 95% 嵌入场景），且内存占用最小；
3. 热重载最优：重编译一个模块 = 纯前端工作，微秒到毫秒级，无原生码缓存失效问题；
4. 沙盒安全面最小：无 JIT 即无 codegen 攻击面，13.3 的字节码结构验证器成本也最低；
5. T2-T4 保留为已记录的可选扩展路线（13.1 不删），启用条件改写为「当性能进入该项目的前三优先级时」。

编译吞吐门槛从 13.1 的「≥100 万行/秒字节码」维持，但含义升级：这个数字不仅是体验指标，是 **AI 修复闭环的时延预算**——千行插件单遍编译 <5ms，AI 一轮「生成→编译→诊断→修复」的机器侧时延 <50ms，远小于 LLM 推理时延，闭环不因工具侧而变慢。

## 14.4 热重载定稿：BEAM 机制的最简投影（建议决策 16）

BEAM 是热重载的黄金标准（Ericsson AXD301 数十年零停机验证），其机制与 Yoru 的对照：

| BEAM 机制 | 必要性根源 | Yoru 的投影 |
|---|---|---|
| 模块双版本共存（old/current） | 运行中进程持有旧代码 | **保留**：重编译产出 v2，v1 保留至无在途调用（refcount 归零后 purge；第三个版本到来时若 v1 仍被持有则拒绝/排队——BEAM 用 kill，Yoru 用拒绝，更安全） |
| fully-qualified call 边界切换 | 进程调用链中途不能换码 | **天然成立**：Yoru 脚本只在入口被调用，调用跨越模块边界即函数调用点，VM 分派时查当前版本 |
| code_change/3 状态迁移 | gen_server 进程堆里持有业务状态 | **整条砍掉**：Yoru 值语义 + 每次调用全新上下文，唯一持久状态在 `flux.storage`/宿主侧，格式迁移是宿主的事，与语言无关 |
| .appup/.relup 发布编排 | 生产零停机升级 | **不做**：2026 Elixir 社区实践共识——绝大多数团队生产走滚动部署，热升级只用于无法断连的窄场景；Yoru 的热重载定位为**开发循环特性**（改码→毫秒级生效→验证），生产更新走宿主重载插件目录 |

**定稿**：reload 协议 = 源哈希变更 → 单遍重编译（<5ms/千行）→ 字节码验证器（13.3）→ 原子替换模块表项 → 在途调用跑完旧版本 → purge。无状态迁移钩子、无升级描述文件、无分布式协调。这是「编译快 + 值语义 + 无状态脚本」三个既有决策的红利兑现，零新增机制。

## 14.5 Rust 交互通道定稿：纯 Rust 闭包，零 C ABI（建议决策 17）

这是 Yoru 相对 Lua/QuickJS 嵌入的**结构性优势**，必须用足。mlua/rquickjs 的所有复杂度大头都来自跨越 C ABI：

| mlua 为管理 C ABI 付出的复杂度 | Yoru 的对应物（纯 Rust VM，无此问题） |
|---|---|
| lua_State 指针 + 栈索引纪律 + StackGuard RAII | 不存在：宿主函数直接拿到 `&mut Vm` 与 Rust 侧 `Args` |
| TypeId 存进 metatable + 运行时借用检查（RefCell 模拟 Rust 借用规则） | **借用这条保留思想**：宿主对象注册进 VM 时存 TypeId + `RefCell` 式借用状态，VM 值层面是不可变别名（值语义），宿主对象是唯一可变点，用类型化句柄 + 运行时借用检查复刻 mlua 的安全模型 |
| RegistryKey（值存 registry 表，Rust 持键） | 保留思想：`HostRef` 句柄让 Rust 侧持有 VM 值，GC 时清理 |
| ToLua/FromLua/ToLuaMulti 转换 trait 全家 | **直接采纳命名**：`IntoValue/FromValue/IntoArgs/FromArgs`，为 stdlib 全类型派生；宿主函数签名经 `HostSig`（12.2）在注册期校验，调用期零反射 |
| async feature（回调返回 Future，VM 挂起） | 保留：宿主函数可声明 async，VM 在 await 点 yield 回宿主 tokio runtime；同步函数零开销路径不变 |
| !Send 默认 + "send" feature | 保留：VM 单线程所有权，跨线程经 channel 传消息（与 FluxDown 插件 runtime 的专用 tokio 池同构） |

**通道分型**（结合 FluxDown 的 flux 门面范式）：
1. **同步宿主函数**（`register_host_fn`）：纯计算/读状态，µs 级，直接调用；
2. **异步宿主函数**：I/O（fetch/fs/task），返回 Future，VM yield；
3. **命令表**（`#[l_command]`，12.2）：宿主在装载期把可用能力注册成可枚举清单——这份清单同时是权限面（13 节 manifesto）、**AI 词汇表**（14.2 检查层 3）、和文档源（单一事实来源三用）。

安全边界不变（13.3 验证器 + 能力注入），但明确一条原则：**语言不内置任何 I/O，所有副作用经注册通道**——这不是限制而是 AI 安全特性：AI 无法调用它没见过的 API，宿主没注册的能力在词法层面就不存在。

## 14.6 基本前端功能覆盖：stdlib 分层定稿

「覆盖基本前端功能」在插件/嵌入场景的正确投影：**语言自带纯数据变换面，宿主注入交互面**。

**L1 内核纯函数层**（语言自带，无副作用，Anka 的主战场——多步数据管道正是前端功能的数据内核）：
- JSON：`parse/stringify`（前端功能的通用数据格式，值语义天然适配）；
- 字符串：插值、`split/join/replace/trim/slice`、正则（单一 regex API，无多写法）；
- 集合：`map/filter/reduce/sort/group`（高阶函数已是设计内核）；
- 时间/时长、URL 解析、base64/hex 编解码、数学（floor/ceil/round/min/max/clamp/lerp）。

**L2 宿主注入层**（任何触碰真实世界的能力）：存储、网络（SSRF 守卫在宿主）、文件、任务、认证、UI 桥（Tauri invoke / webview 事件）——与 FluxDown `flux.*` 门面同构，能力即权限，清单即词汇表。

原则：**L1 冻结为 AI 可依赖的稳定词汇表并随语言规格分发；L2 每宿主一份清单**。前端功能的「基本」部分（数据变换、格式化、校验）全部落在 L1——AI 无需知道宿主就能写出可验证的变换逻辑，宿主交互集中在少量入口函数，出错面最小。

## 14.7 砍复杂语法：规范形式审计清单（建议决策 15 的一半）

按 Anka 四原则对 02-语法规范做逐条审计，产出**砍/留/规范化**清单：

| 项 | 判定 | 依据 |
|---|---|---|
| 多种循环写法（for/while/loop 若并存） | **砍到一种**（for-in 为主，while 保留） | 规范形式原则；循环是 AI 排序/边界错误高发区 |
| 三元 vs if 表达式并存 | **规范化**：`if` 是表达式，砍掉独立三元运算符 | 一种写法；if 表达式已覆盖 |
| 字符串拼接 vs 插值并存 | **规范化**：插值为唯一推荐，拼接保留于 stdlib join | 插值减少类型/转义错误 |
| 解构赋值 | **砍出 MVP**（02 已最小化，确认不做嵌套解构） | 模式匹配是 AI 错误放大器；显式字段访问更可读 |
| 生成器/迭代器协议 | **不做**，迭代经 for-in + 高阶函数 | 状态机语法复杂度全砍 |
| async/await 语法 | **只留 await**（异步性由宿主函数声明承载，Yoru 侧无 async fn） | AI 对并发语法错误率高；VM 层 yield 机制（14.5）够用 |
| 运算符过载 | 维持 13.5 的协议约定（P1） | 受约束的扩展点，编译期解析 |
| 类/继承 | 不做（维持） | struct + 函数已覆盖插件场景 |
| 宏 | 不做（维持 13.2） | 展开耗时无上界，与编译快冲突 |
| 冗长关键词 vs 符号 | **倾向关键词**：新增语法优先用词不用符号（如 `and/or/not` 已如此） | Anka 冗长关键词原则 |
| 中间结果命名 | **lint 级强制**：连续链式调用 >2 步要求命名中间值 | Anka INTO 原则的 Yoru 投影；防长链状态丢失 |

审计的元规则：**任何新语法提案必须回答「AI 有没有第二种写法能达到同样效果」——有，就砍或合并**。02 的 BNF 因此新增一条冻结条款：BNF 产式数量设为受控指标（目标 <60 产式），随 prompt 资产分发。
