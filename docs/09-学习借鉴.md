## 9.1 执行引擎（解释器/JIT）

### LuaJIT（trace JIT 巅峰）
原理：汇编级快速解释器+两级执行。hotcount 热点计数（循环命中减2、函数减1，默认循环 56 次归零触发）；热点循环记录线性 trace 转 SSA IR（约 50 条指令），经 FOLD 引擎优化后编译机器码；guard+snapshot 支撑类型特化与 bailout；side trace 与 trace stitching 覆盖分支；分配下沉与 deopt 耦合；FFI 的 C 调用可内联进 trace；NaN-tagging 统一 64 位值。

- 采用（P2）：热点计数模型、guard+snapshot（Yoru 的静态类型可消除大部分类型 guard，仅 dynamic 边界需要）、宿主 FFI 调用内联目标、happy path 内联+fallback 分派（Rust match 分派热路径）。
- 不采用：完整 trace 编译器。理由：多平台汇编后端维护成本极高——LuaJIT 因此永久锁死 Lua 5.1，语言演进被 JIT 拖死是最大教训。Yoru 采用解释器+函数级 JIT（Cranelift），JIT 建立在稳定字节码+独立后端上，绝不让 JIT 锁定语言演进。
- 借鉴（P1）：NaN-tagging 值编码（P2 与 JIT 同批换装）。

### Lua 5.4（寄存器式 VM）
原理：32 位指令、7 位 opcode、5 种编码格式（iABC/iABx/iAsBx/iAx/isJ）；k-bit 一位切换寄存器/常量池操作数；OP_LOADI 直接编码 17 位立即数；RETURN0/1 内联帧弹出；OP_CALL 用 goto 而非 C 递归（所有 Lua-Lua 调用共享一个 C 帧，深递归不溢 C 栈）；FORLOOP 无符号算术预计算迭代数 count=(limit-init)/step，step=1 免除法；运算 fast path 直接跳过下一条 metamethod 指令（零成本慢路径）。效果：fib 调用约 8 条指令（CPython 约 17 条）。

- 采用（P1，改寄存器式）：指令集内建优化（立即数/常量池位域）；FORLOOP 无符号预计算；RETURN 快速路径；同帧调用——Yoru 的 Rust 实现必须用显式调用栈而非 Rust 递归（沙盒栈深控制关键）。
- 关键教训：指令编码的巧妙 > 解释器循环的英勇。
- 借鉴（P1）：upvalue open/closed 机制（Yoru 值语义下仅需 cell 化捕获变量）。

### V8
- 借鉴：隐藏类/shape 思想——但 Yoru 结构体值语义天然固定形状，无需动态 shape 缓存，这是相对 JS 的结构性优势（[01-语言目标](01-语言目标.md)）；PIC 多态内联缓存（P1，与 QuickJS 同源）。
- 不采用：多层编译器+深度 deopt 基础设施（复杂度极高）。Yoru 用 guard+bailout 简化版，静态类型消除大部分推测需求。

### QuickJS
编译期栈深、闭包优化、行号压缩、opcode fusion/PIC（见 [04-执行引擎](04-执行引擎.md)）。

## 9.2 编译器与代码生成
- Cranelift（已采用，[05-后端取舍](05-后端取舍.md)）：SSA block params、无 UB、编译快约 10 倍、防恶意输入。
- LLVM（已采用，可选发布后端）：优化管线（LTO/向量化）。
- rustc/Salsa 增量查询：按依赖图缓存结果。借鉴（P1）：模块级依赖图+结果缓存的轻量实现，不引入完整查询框架。
- 类型检查优化：双向类型检查（MoonBit 采用，Yoru 已确认）；HM Algorithm W 为基础；局部类型推断（Luau 计划、MoonBit 采用，Yoru 已确认方向）。

## 9.3 内存管理
- Perceus（MoonBit）：引用计数+机会性复用（编译期静态分析插入释放/复用，Wasm/C 后端无循环检测）。借鉴（P2）：字节码编译期拷贝消除（值语义下复用更易，字节码层栈复用分析）。
- Immix（mark-region GC）：未来 GC 升级方向（P2/P3 记录）。
- 区域/arena：热重载模块卸载整片释放（已写 P2）。
- 字符串驻留与小对象优化（P1）。

## 9.5 嵌入与 FFI
- Lua C API：栈式交互、宿主不触碰 GC 内部对象、错误以对象返回（protected call）。采用（阶段1 C ABI）：值栈+错误码约定；宿主 API 用句柄+Result（Rust 所有权，不用裸指针暴露 GC 对象，规避 Python C API 悬挂引用问题）。
- WASI/组件模型：不采用（进程内嵌入，非跨进程组件）。
