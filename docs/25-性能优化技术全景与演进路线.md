## 1. 图灵完备性裁决（以代码为准）

**结论：语言核图灵完备；默认 VM 配置下是「保证终止的有界计算」——这是设计特性，非缺陷。**

| 层面 | 证据 | 裁决 |
|---|---|---|
| 语言核 | `while`/`break`/`continue`（lexer.rs L457-475）+ 可变数组（`SetIndex`/决策 80 下标赋值）+ 无界 `i64` 算术 + 一等函数/闭包/递归 | **图灵完备**。无界 while + 可变内存即经典 WHILE 语言模型；闭包 + 递归提供 λ 可计算性 |
| VM 层 | 决策 71 三限：`max_instructions`/`max_call_depth`（默认 256）`max_heap_bytes` + 决策 79 run 作用域 + deadline/interrupt | 数学上退化为**有界自动机**——每个程序必然终止。与 WASM 引擎可配内存上限、Cloudflare Workers CPU 限额同范式：**沙盒运行时的标准语义**，宿主嵌入场景恰恰需要「脚本保证停机」 |
| 恢复完整 TC | 宿主把三限设为 `usize::MAX` 且不设 deadline | 完整图灵完备 |

关键澄清：**「受限 ≠ 不完备」**——图灵完备性是语言（指令集 + 内存模型）的属性，资源限制是执行策略。Yoru 的独特卖点恰是：TC 的表达力 + 沙盒的终止性保证同时成立（多数 TC 语言两者不可兼得：CPython 的 while 可永不上限）。

## 2. 不变量（所有优化的硬边界）

1. **语法零变更**：以下全部技术均为 VM/lowering/运行时层，用户代码与 LBC0 语义可观测面不变（除耗时）。
2. **优先级铁律**：执行性能排第 4。任何优化若损害编译速度/启动（当前 32ms）/诊断质量，一票否决——这就是为什么 P0 全是解释器内功而非 JIT。
3. **基线门控**：每项优化以 24 号基线回归验证（插入排序 + 未来第二/第三负载），**无数据不合入**。
4. **沙盒语义不动**：三限/中断/可观测性（决策 72）必须在优化后仍然逐项可触发。

## 3. 技术全景对比（按层，全部为业界已验证技术）

### A. 解释器分派层（P0 主战场，对应 6.5x 差距的大头）

| 技术 | 代表项目 | 机制 | 对 Yoru 适用性 | 成本 | 阶段 |
|---|---|---|---|---|---|
| **超指令（superinstructions）** | CPython（PEP 659 数据：10% 来自它）、Lua 5.4 | 高频指令对融合为单条（如 `GetLocal+PushInt` → 一条），省一次分派+栈操作 | **极高**。450 万次内层操作里 `LoadLocal/Const + Cmp + JumpIfFalse` 全是固定配对 | 低：lower 期模式匹配，不改 VM 语义 | 5 |
| **下标/字段访问 IC（内联缓存）** | V8 hidden classes、Deutsch & Schiffman '84、PEP 659 quickening | 指令旁缓存「上次命中结构 + 偏移」，命中走快路径 | **高**。`GETFIELD/SETFIELD` 当前线性扫 KV；struct 已有字段序号但 Map 仍扫描 | 中：LBC0 需扩展指令旁缓存区（向后兼容：缓存段可选） | 5-6 |
| **寄存器 VM 改造** | Lua 5.4/LuaJIT/V8 Ignition（寄存器+累加器） | 操作数显式编址，消 push/pop | **中高**。已有 `max_stack` 与局部槽机制，改 lowering 编译为寄存器形式。业界共识：同语义下指令数 -30~50% | 高：触及全部 opcode 语义，需差分测试 | 6 |
| **分派微观优化** | QuickJS（紧凑 switch）、CPython（computed goto，10-15%）、Ruby 3.14 tail-call 解释器 | 每指令尾部间接跳转 + 独立分支预测历史 | **中**。Rust 无稳定 computed goto；实测当前 `loop+match`（LLVM 跳转表）后按 profile 决定是否上 tail-call（`become` unstable）或宏展开 threaded code | 中 | 5-6 |
| **值表示特化（SMI 小整数）** | V8（Smi）、LuaJIT（number 双用）、CPython | 小整数不装箱，直接嵌指针位 | **中**。当前 `Value::Int(i64)` 已是 enum 内嵌（非指针装箱），瓶颈更多在 `Rc<RefCell>` 原子计数上 → 见 F 层 | 中 | 6 |

### B. 特化自适应解释器（P1，CPython 3.11 +25% 的同款路线）

| 技术 | 出处 | 对 Yoru 适用性 | 阶段 |
|---|---|---|---|
| **Quickening（指令原地改写）** | PEP 659：自适应指令观察类型后改写自身为特化版本 | 高。Yoru 值面窄（9 变体），特化收益密度高于 JS：`Add` → `AddIntInt`（i64 直算，免 match 分派）覆盖绝大多数热路径 | 5-6 |
| **按调用点单态缓存** | V8 monomorphic→polymorphic→megamorphic 梯度 | 中高。宿主函数/内建调用点缓存上次命中 id | 6 |
| **deopt 纪律** | PEP 659 核心洞察：**单指令粒度特化 → deopt 平凡**（不存在区域中途退出） | 直接采纳为设计原则：Yoru 若上特化，学 PEP 659 而非区域特化，免写 OSR | 5-6 |

### C. JIT 分层（P2，阶段 6，以 benchmark 驱动立项）

| 路线 | 代表 | 对 Yoru 的裁决 |
|---|---|---|
| **Tracing JIT** | LuaJIT（hot threshold ~56 次迭代 → 记录 → SSA IR → FOLD/CSE/DCE/sinking → 机器码） | 峰值最高但工程量极大（LuaJIT 是 Mike Pall 级人力）；嵌入场景脚本短、热点小，**暂不立项** |
| **Method JIT + 分层** | HotSpot C1/C2（~1 万次阈值）、V8 Sparkplug(+5-15%)/Maglev/TurboFan | 分层思想采纳：若立项 JIT，先做 baseline（见下）再谈优化编译器 |
| **Copy-and-patch** | CPython 3.13/3.14（PEP 744，Xu & Kjolstad '21）：编译期生成机器码模板，运行时仅 memcpy+补洞，「75% 收益 25% 工程量，比 LLVM JIT 快 1000x」 | **P2 首选**。与 Yoru 契合点：① 编译快铁律不受损（模板预生成）；② 模板由解释器同一实现派生→语义天然一致；③ 适配 LBC0 定长指令。先决条件：值表示稳定（F 层先行） |
| **Cranelift 后端** | Wasmtime/Cranelift、V8 Liftoff（单遍基线 >100MB/s + TurboFan 分层） | 备选：LBC0→Cranelift IR→原生，安全且现成，但引入大依赖、启动内存涨——与「轻嵌入」定位权衡后裁决 |
| **OSR（栈上替换）** | HotSpot/V8 | 短脚本场景价值低（循环 ~450 万次才值得），Yoru 嵌入脚本多为短任务；**不做**，热点循环靠调用级替换 |

## 4. 迭代路线（按铁律排序，全部 benchmark 门控）

| 批次 | 内容 | 预期收益（对 6.5x 差距） | 前置 |
|---|---|---|---|
| **P0a**（阶段 5 立即） | ① profile 释疑（perf/VTune 定位分派 vs Rc vs 访存占比）；② 全局分配器试切（mimalloc）；③ 超指令第一批（`LoadLocal+Const`、`Cmp+JumpIf`、`GetLocal+Index`）；④ **LBC0 直载缓存**（启动 32ms→~16ms，服务铁律第一项） | 分派层 ~10-20%；启动 ~2x | 24 号基线已有 |

> **2026-10-13 P0a 部分落地**（① ② ③ 完，④ 顺延）：
> - **① profile 释疑**：以 **VM opcode 直方图**替代 perf/VTune（Windows 无 perf；`yoru run --stats`，`enable_op_histogram` 默认零开销）——sort 负载 58.5M 指令分布：LoadLocal 30.8% / Const 11.5% / JmpIfNot·GetIndex·Pop·Nil 各 7.7%，超指令选型由此驱动而非猜测。
> - **② mimalloc A/B**：`--features mimalloc` 开关实测 **反慢 ~9%**（median 730.9 → 795-800ms，两轮一致）——Windows 堆在 Rc 小分配负载下已足够优，**证据不支持采纳，已撤销**，数据留档。
> - **③ 超指令第一批**：`JmpIfNotLt/Le/Gt/Ge`（0x7C-0x7F，Cmp+JumpIf 融合）+ `GetIndexLL`（0x67，双局部槽下标读）——lower 窥孔自动生成；配套 **`Nil;Pop` 后处理窥孔 pass**（指令 -15.4%；**发射期窥孔已证伪**：块尾值 Nil 可能是跳转目标，08_physics 回归最小复现后改为「跳转目标集合保守 + 偏移重算」pass）。
> - **量化（benchmarks/sort，N=3000 插入排序）**：指令 58.5M → **36.0M（-38.4%）**；median 730.9ms → **~540-567ms（-24%±噪声）**；净执行 ~705 → ~520ms（-26%）；启动 32ms 保持（编译面无损，铁律 ✓）；checksum 逐位一致。对 QuickJS-ng 净执行差距 ~2.9x → ~2.1x。
> - **④ LBC0 直载**落地（2026-10-13，`yoru run foo.yoruc`）：deserialize（magic/version/CRC32 完整性）+ verify_module（validate-before-use 不豁免自产字节码）→ 直入 VM。e2e：sort 与 std-import 模块直载输出逐位一致；坏字节 → CRC32 mismatch 结构化拒绝 exit 1；check/build 误入 `.yoruc` → 诚实指引。**预测修正（诚实）**：原估「启动 32→~16ms」证伪——实测 spawn+init 地板 ≈28ms，CLI 小模块前端仅 0-5ms（tiny run min 36.6→28.9，-21%；sort 全程噪声内持平）。真实收益面 = **嵌入进程内加载**（无孵化，前端全链随模块大小线性节省）+ 产物分发工作流（CRC 完整性把关）。进程孵化地板属 OS 层，VM 侧不可达。
| **P0b**（阶段 5） | IC 基建：GETFIELD/SETFIELD 单态缓存段 + `with_map_mut` 局部快路径扩展（决策 80 族推广） | 访存热路径 ~20-40% | P0a①数据 |

> **2026-10-13 P0b 落地（形态升级：静态槽位表 > 单态缓存）**：
> - **实现**：字段序由 struct 声明表静态决定（NEWSTRUCT 按表序对齐），故 (struct_id, fid) → slot 是纯静态事实——`load()` 装载期一次性预计算 `struct_slots[struct_id]` = (fid, slot) 升序表，GetField/SetField 快路径 O(log k) 二分 + **fid 复核**（防宿主构造值 `struct_id: u32::MAX` 自对齐漂移），未命中回退原线性扫描（语义逐位保留，Y-R9012 错误面不变）。较原设计「按站点单态缓存」的优势：零失效、无站点存储、**天然多态**（同一站点多 struct 类型亦精确，无需 megamorphic 退化路径）。
> - **顺手修掉的真热点**：GetField/SetField 成功路径此前每次调用 `field_name()` **format! 堆分配 String**（纯为错误路径服务）——改为懒构造，Map/错误分支才付代价。
> - **量化（新增 benchmarks/structs：3 字段 struct 展开更新 + 6 读/迭代 ×100 万，--heap-mb=1024）**：median **1441.1 → 936.7ms（-35%）**，checksum 逐位一致；**+1 回归测试**（A{x,y}/B{y,x} 跨布局消歧，快路径 fid 复核防串桶）。sort 基准零字段操作（直方图实证），基线持平（511-541ms vs 500.7，min 差 ~2% 属环境噪声）。
> - **验证**：189 全绿 / clippy 零 / fmt 干净 / fuzz 5 万 panic-free。宿主构造 struct（demo summarize 测试）原样通过——回退路径保住自对齐语义。
| **P1**（阶段 5-6） | Quickening 特化解释器（`AddIntInt` 等算术族 + deopt 平凡原则）；`Rc` 热路径削减（smallvec 内联/借用期复用） | 算术密集 ~30-50% | P0b 缓存段机制 |

> **2026-10-13 P1 首步落地 + Quickening 证据裁决**：
> - **取指合并（已落地）**：step() 单次 `frames.last_mut()` 取 (proto, pc) 并推进（取代 last()×2 + last_mut() 三次尾访问）+ `Frame.proto` 直存（省每条一次 Rc 解引用）。受控 A/B（stash 往返同态）：sort min 516.1→510.3 / median 537.7→530.9（**~1%**）——方向一致但远小于模型预期：Vec 尾访问实为 len 比较 + 良好预测，Rc 指针 L1 命中。严格减法保留，热点裁决价值更大。
> - **Quickening（诚实延后）**：算术臂已是 `(Int,Int)` 首匹配 + 融合比较共用 cmp_values（Int/Int 首臂），类型分派的内层重分派仅 ~3-5 cycles/条（sort 39 cycles 预算的 <13%，且 Add+Sub 仅占指令 12.5%）——**实测建模收益 ~1%，不抵架构成本**（in-place 自改代码需 Vm 持有代码副本 + deopt 簿记 + 直方图映射 + verify 交互）。P1 预估「算术密集 30-50%」不成立于当前负载形态；**触发条件**：出现算术/浮点密集的真实工作负载（直方图 Add/Sub/Mul/Div 占比 >25%）再立项，届时以 owned-code 副本为基建第一步。
> - **热点再定位（本批数据）**：每指令 ~39 cycles 的构成里，取指脚手架已被本批压缩至次要——剩余大头属架构层：opcode dispatch 间接跳转、栈式 push/pop 的 Value 宽度拷贝、Vec 边界检查。这些归 **P2 门槛**（寄存器 VM / copy-and-patch），不做局部补丁。
| **P2**（阶段 6，立项评审） | copy-and-patch JIT 模板（先 baseline 无优化级）或 Cranelift 后端二选一；寄存器 VM 改造评估 | 3-10x（对齐/超越 QuickJS 带） | P1 落袋 + 值表示冻结 |
| **P3**（随需） | 异步 IO 能力包（io_uring 后端）、结构化并发预算继承、零拷贝宿主能力 | IO 场景 | 真实嵌入场景数据 |

**明确不做**（证据驱动否决，留档防复燃）：tracing JIT 全套（人力不匹配）、OSR（短脚本场景）、语言层 GC 环检测（G10 已裁决）、`bytes` 原生值类型（语法冻结）、PGO 训练管线（无部署规模）。

## 4-b. 激进优化调研与数学验证（2026-10-13，多源调研批次）

三条调研线的证据与取舍（来源：pliniker dispatch 实验 / daily.dev tail-call interpreters / PEP 744+pydevtools copy-and-patch / CUDA Programming Guide 6.1 / GPUOS arXiv 2604.17861）：

| 路线 | 证据 | 取舍 |
|---|---|---|
| computed goto / tail-call threading | Haswell+ 宽发射 CPU 上 branch predictor 使单 match ≈ computed goto（差异 <5%）；direct tail-call threading 在 M1 实测快 ~37% 但需 nightly `explicit_tail_calls` | **拒绝**：Yoru 目标 x64 Windows（BP 已消除差异）+ 稳定铁律（nightly 不可入生产） |
| copy-and-patch JIT（stencils） | CPython 3.13→3.15 三年才 5-6%（x64 Linux）；需构建期 LLVM stencil 管线 | **登记远期**：工程量/收益比当前阶段不成立；若未来做 Tier2 micro-op 化再评估 |
| GPU 后端（CUDA NVRTC/PTX） | kernel launch 税 ~5μs（小操作密集负载 100 次提交=0.5ms 协调成本）；驱动 JIT 缓存随驱动升级失效；persistent kernel + 设备函数指针表可做常驻解释器（GPUOS 15.3x 但限 ML 微批场景） | **登记远期可选后端**：与嵌入可移植性铁律冲突（GPU 可用性不保证/安全面爆炸）；数据并行场景出现时再立项 |

**数学验证 + 已落地：中断节流倒数计数器**。原 `instructions % check_interval` 在热路径为运行时变量 64 位除法（check_interval=10_000 非二次幂，x64 div 无法强度削减，~20-25 cycles/条）；每指令总预算 ~43 cycles（36M 指令/520ms @3GHz）→ 调度税占比可达一半。倒数计数器（dec+cmp ~1 cycle）触发点逐位等价（第 k·interval 条）；`max(1,·)` 防御 interval=0（原实现为除零 panic 面）。**实测：sort median 540-567 → 496.6ms（-8~9%），checksum 逐位一致**。上限语义注记：max_instructions 保留每条精确检查（cmp 便宜、上界精确，不并入节流点——避免资源限额语义弱化）。

## 4-c. 稳定性与极限压测档（2026-10-13，S 线批次）

用户命题「长期运行稳定性 / 语言边界压测 / 极端环境抗冲击 / 停机安全保证 / 底层压榨验证」的落地盘点与新增：

**既有防线盘点（本批实证确认，非新增）**：资源四限（指令/调用深度/堆字节/截止时刻，决策 71/72）各有触发测试；run 作用域预算重置（决策 79，长驻宿主不饿死）；解析器嵌套深度限制（拒绝而非爆栈）；宿主 panic 边界（catch_unwind → 结构化 Y-H9001，不穿透 VM）；循环引用 deep_eq/display 深度截断；算术全算子 checked（Add/Sub/Mul/Div/Mod/Neg 六算子 debug 构建零 panic 面）；词法整数字面量溢出 → 诊断降级。

**本批新增**：

1. **CLI 停机安全三旋钮**（决策 71 的 CLI 面）：`yoru run --max-instructions=N --heap-mb=N --deadline-ms=N`——「跑别人给的脚本」场景收紧（沙箱化）与放宽（重负载）均可表达；解析失败 = 用法错误 exit 2。e2e 实证：死循环脚本在三旋钮下分别以 Instructions/Deadline/HeapBytes 优雅停机（exit 1），坏值 exit 2。
2. **长跑确定性测试**：200k 迭代 checksum（>1M 指令）双独立 VM 逐位同结果 + 指令数一致（调度透明性契约）。
3. **停机时延量化界**：中断钩子第 k 次触发时 `instructions ≤ k·check_interval + 1`——倒数计数器触发点契约的测试化（探针实证 fire#8 恰在 512 = 8×64）。
4. **极值算术矩阵**：MIN-1 / MIN×-1 / MIN÷-1 / MIN%-1 / -MIN 全部结构化 Y-R9001（MIN÷-1 与 MIN%-1 是 debug 构建经典 panic 面，checked_* 全拦截）。
5. **退化输入面**：空源 / 仅注释 / 缺 main → 结构化 Y-R9000，不 panic。
6. **无界增长面**：循环字符串拼接 → 堆限逐次检查拦截（指令预算双保险断言）。
7. **语义缺陷修复（const 折叠透明性）**：`fold_const` 原用截断 `checked_div/checked_rem`，与 VM 运行时 `div_euclid/rem_euclid`（决策 44 floor 语义）分叉——`(0-7)/3` const 折叠 -2 vs 运行时 -3、`(0-7)%3` 折叠 -1 vs 运行时 2（红证 "false/false" 实锤）。修复为 `checked_div_euclid/checked_rem_euclid`，const 折叠与运行时语义逐位一致，回归测试锁定。

**吞吐基线（本批复测）**：sort median 500.7ms（噪声内持平 496.6）；36.02M 指令 / 净执行 ~469ms → **~76.8M instr/s**；启动 31.5ms 保持（铁律 ✓）；checksum `149858500 0 99973` 逐位一致。验证面：workspace **188 全绿**（+6）、clippy 零、fmt 干净、doctest 4、examples 11+1+demo 编译面、fuzz 10 万 panic-free（见 CHANGELOG）。

**遗留登记**：`Cell::clone` 是值拷贝非共享——共享观测必须 `Rc<Cell>`（测试写作实证教训，探针法定位）。
