## 15.1 词法规则

```
identifier ::= [A-Za-z_][A-Za-z0-9_]*
integer    ::= [0-9]+
float      ::= [0-9]+ "." [0-9]+
string     ::= '"' ( plain_char | escape | "${" expr "}" )* '"'    # 插值是拼串唯一形式
comment    ::= "//" 至行尾 | "/*" ... "*/"
```

- **语句终止 = 换行**。行尾为二元运算符、逗号、未闭合括号时语句延续（确定性规则，无 ASI 猜测）。
- 无缩进语义；缩进纯美观。
- 逻辑运算用符号 `&& || !`（TS/Rust 高先验、单 token）；「冗长关键词」原则只约束新语法，不推翻高先验符号。
- 前缀 `!` = 逻辑非，后缀 `!` = Option 解包——位置分离，无歧义。

## 15.2 语法规则（EBNF v1）

```
program       ::= { top_decl }
top_decl      ::= import_decl | type_decl | fn_decl | struct_decl | tag_decl
                | protocol_decl | impl_decl | const_decl

import_decl   ::= "import" identifier "from" string
type_decl     ::= "type" identifier "=" ( type | "distinct" type )
const_decl    ::= "const" identifier ":" type "=" expr            # 顶层必标

fn_decl       ::= "fn" identifier "(" [ param { "," param } ] ")" [ "->" type ] fn_body
fn_body       ::= block | "=" expr                                # 块体/表达式体一个轴
param         ::= identifier ":" type

struct_decl   ::= "struct" identifier "{" field_decl { field_decl } "}"   # 字段换行分隔
field_decl    ::= identifier ":" type
tag_decl      ::= "tag" identifier "=" variant { "|" variant }
variant       ::= identifier [ "(" type ")" ]

protocol_decl ::= "protocol" identifier "{" { protocol_fn } "}"   # 仅签名，默认方法 P2
protocol_fn   ::= "fn" identifier "(" [ param { "," param } ] ")" [ "->" type ]
impl_decl     ::= "impl" identifier "for" identifier "{" { fn_decl } "}"

block         ::= "{" { stmt } "}"
stmt          ::= let_decl | expr | while_stmt | for_stmt | return_stmt | throw_stmt | block
let_decl      ::= "let" [ "mut" ] identifier [ ":" type ] "=" expr
while_stmt    ::= "while" expr block
for_stmt      ::= "for" identifier "in" expr block
return_stmt   ::= "return" [ expr ]
throw_stmt    ::= "throw" expr

expr          ::= literal | identifier | postfix | unary | binary | assign
                | lambda | if_expr | match_expr | try_expr | await_expr
                | struct_lit | group
postfix       ::= primary { "(" args ")" | "." identifier | "[" expr "]" | "!" }
primary       ::= literal | identifier | lambda | if_expr | match_expr
                | try_expr | await_expr | struct_lit | group
unary         ::= "!" expr | "-" expr
assign        ::= identifier ( "=" | "+=" | "-=" ) expr            # 赋值仅限标识符
lambda        ::= "fn" "(" [ param { "," param } ] ")" fn_body
if_expr       ::= "if" expr block [ "else" ( if_expr | block ) ]
match_expr    ::= "match" expr "{" { match_arm } "}"
match_arm     ::= pattern "->" ( expr | block )
pattern       ::= literal | identifier | variant_pattern | "_"      # 无解构模式（14.7）
variant_pattern ::= identifier [ "(" identifier ")" ]
try_expr      ::= "try" expr
await_expr    ::= "await" expr
struct_lit    ::= identifier "{" [ field_init { "," field_init } ] "}"
field_init    ::= identifier ":" expr
group         ::= "(" expr ")"
literal       ::= integer | float | string | "true" | "false" | "nil"
```

类型文法（与表达式文法严格分离）：

```
type      ::= prim | named | option | result | list | map | fn_type | record | "Json"
prim      ::= "int" | "float" | "bool" | "string" | "unit"
named     ::= identifier [ "<" type { "," type } ">" ]
option    ::= type "?"
result    ::= "Result" "<" type "," type ">"
list      ::= "[" type "]"
map       ::= "[" type ":" type "]"
fn_type   ::= "(" [ type { "," type } ] ")" "->" type
record    ::= "{" [ identifier ":" type { "," identifier ":" type } ] "}"
```

二元运算符优先级（低→高）：`|> || && == != < > <= >= | ^ & << >> + - * / %`。`|>` 优先级最低、左结合；`a |> f(b)` 即 `f(a, b)`——纯求值位置变换，不可重载、不引入新概念。运算符过载以协议约定（编译期解析，P1，13.5）。

### 隐式转换矩阵（第四轮定稿，2026-10-11）

| 转换路径 | 规则 | 依据 |
|---|---|---|
| int ↔ float | 永不隐式，显式 `as`；单宽度无 i8..i64 | 决策 26；JS 2^53 陷阱 / Rust Go Swift Zig 一致拒绝 |
| T → T? | **隐式允许**（安全加宽） | 决策 27；Swift 先验；AI 不忘包 Some() |
| T? → T | 永不隐式，`!` 显式解包 | 隐式解包让 nil 检查失效，无一语言允许 |
| 插值 `${e}` | 自动显示转换**仅限显示位**（Rust format! 同款）；值语义不变 | 显示 ≠ 值转换；JS `[object Object]` 是反面教材 |
| bool truthiness | 不存在；`if` 条件必须 bool | Elm beginner hint 实证 |
| distinct 双向 | 显式 `as`（决策 23） | — |
| dynamic | 已删除（决策 28） | Json 类型 + 收窄替代 |

推断模型定稿：**静态类型 + 双向局部推断 + 顶层必标**；不采用全局 HM 统一——错误消息指离病因（Elm 演讲实证：加注解后错误立刻变准），且全局统一拖慢编译。标注税花在签名位（typeck 与 AI 词汇表最需要的位置）。

### 学习成本审计（第三轮：Jai 完整扫描 + Carbon 反例，2026-10-11）

Jai（2026-10-08 随游戏出货，80k 行 <1s，25 万行/秒）证明：**数据导向靠减法达成，不靠语法改造**——C 形语法 + `#soa` 一个标注，其余全是纪律。Carbon 反例（LWN 2025 RustConf 报道）：语法偏离到会疏远目标人群（fn/func/proc bikeshedding、`[]` 泛型）。据此对草案逐项先验审计：`fn/let/let mut/struct/as/match`（Rust+TS）、无分号（Go/Swift/Kotlin）、tag union（TS 联合类型）、`T?`+`!`（Swift 十年先验）、插值（JS/TS）、无类（Go/Rust 共识）、`[K: V]`（Lua/Go）全部零成本；**真租金仅两处**——`try` 前缀（一句话可教，Anka 冗长关键词原则）与能力参数（概念新、语法旧）。学习负担低于 Rust（无所有权/生命周期/借用标注）。

`let mut fn return if else for in match struct tag protocol impl type import const as try throw await nil true false distinct`

## 15.4 规范形式审计表（一操作一形式）

| 操作 | 唯一形式 | 被砍掉的替代写法 |
|---|---|---|
| 遍历循环 | `for x in xs` | foreach/迭代器协议/`loop` |
| 条件循环 | `while` | do-while、until |
| 条件取值 | `if` 表达式 | 三元 `?:`（if 表达式覆盖） |
| 形状分派 | `match`（穷尽检查） | switch、级联 if |
| 拼串 | 插值 `"${e}"` | `+` 拼串、concat |
| 类型转换 | `as` | `::`（02 的第二种转换已删，AI 先验中 `::` 是路径符） |
| Result 传播 | `try e` | `?` 后缀（被 Option 占用） |
| 多步变换 | `\|> f(x)` 管道 | 嵌套调用 `f(g(xs))`、隐式迭代器（Jai `it`） |
| Option 解包 | `e!` | 隐式解包、`?.` 链 |
| 返回 | `return` | 隐式尾表达式（两种返回形式即两种形式） |
| 构造 struct | `Type { f: v }` | 位置参数构造、构造函数重载 |
| 声明 | `let` / `let mut` / `const` | `var`、类型后置（`x: int = 3` 仅顶层必标位） |
| 副作用 | 能力参数 `ctx: Ctx` | 全局命名空间、隐式 context、效果标注 |

相对 02 旧 BNF 的删改清单：**删**分号、`::` 转换、`async` 块/关键字（异步性由宿主函数声明承载）、`async_expr`；**改** if_stmt/match_stmt 统一为表达式（控制流全表达式化，语句位即 unit 表达式语句）；**增** struct 字面量、tag_decl、protocol/impl、distinct、插值、后缀 `!`、map 类型。

实现注意：struct 字面量不得直接作为 if/while 条件头部（`if Vec3{x..}.x > 0` 需加括号）——消除 Rust 同款控制流歧义，一条规则。

## 15.5 数据导向 × 多范式 × 组合（本轮取舍定稿）

- **数据导向的 Yoru 投影**：不做布局层 DOD（Odin `#soa`/Jai SOA 属系统语言，字节码 VM 无意义，留档 T2+ 原生层）；取其精神——struct/tag 唯一数据组织、变换管道为主语、match 解构形状。Jai arena 思想取其机制：VM 每调用一 arena，调用末整体回收（与值语义、无状态热重载互为犄角）。
- **组合大于继承**：继承三用途三替代——is-a → tag union（穷尽 match）；能力 → protocol（显式 impl）；实现复用 → 组合 + 显式委托（无字段提升/using，名字来源必须可 grep）。
- **Odin context 系统**：取「环境能力可注入」模式，弃隐式传递（决策 22）——Odin 证明价值，Yoru 用显式参数更硬地兑现。
- **Koka 效果系统**：取「副作用进签名」目标，弃行多态机制（类型系统复杂度之王，与编译快冲突）；能力即参数以零类型系统代价获得 ~80% 收益。
- **distinct 类型**（决策 23）：`type UserId = distinct int`，构造 `UserId(5)`，双向显式 `as`；P1。

## 15.6 AI 纵深：三重身份 × 三条铁律

1. **作者（生成）**：规范形式 + 低 token + 高先验迁移。证据：SimPy 13.5%/10.4% token 节省、Anka +40pp、TS 比 JS 贵 31% 的标注税/标点税。
2. **读者（正确调用）**：**签名即完整契约**——顶层必标 + 能力参数使一个签名同时声明输入/输出/副作用/失败模式四元组；AI 读签名即可调用，无需读实现。API 幻觉根治 = 签名完备 + 词汇表机械导出（Text2DSL：注入后 98.6-99.4% 句法有效率）。
3. **审稿人（验证）**：**语义可局部判定**——值语义 + 无宏 + 无隐式提升 + 协议编译期解析 ⇒ 表达式语义由局部签名完全决定，AI review 无需全程序分析。

总纲：**每个语法 token 双向付租——生成时便宜，验证时可判定。**
