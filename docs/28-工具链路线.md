## 2. 各线首步方案

### 2.1 formatter（F）

> **【29 号审核修订，2026-10-12】** 本小节管线设计经对抗审核修订：AST 打印推翻改 token 流空白重写（D1）；注释保真前置缺口实锤，F0 lexer trivia 扩展先行（D2）；验收协议换 token 序列 + 结构投影双断言（D3）。以 **29 号为准**。

- **管线**：`src → parse → AST → 格式化打印 → src'`，禁 re-parse 后 AST 不等（往返保真是唯一硬验收）。
- **风格基线**（从 19 号定稿与 examples 惯例反推，先 80% 后迭代）：
  - 4 空格缩进；块 `{` 不换行；`fn` 签名单行超 100 换参数
  - 空行规则：顶层项之间 1 行；块内不主动加/删连续空行（保 1）
  - 运算符两侧单空格；`:` 后空格 `:` 前 0（与 examples 一致：`fn f(x: int) -> int`）
  - 尾随逗号：多行参数/结构体字面量加（diff 友好）
  - **注释与字符串字面量逐字节保真**（fmt 不碰 token 文本，只重排空白结构）
- **验收**：① `fmt(fmt(x)) == fmt(x)`（幂等）；② 对 examples/ 全部 11 篇 + benchmarks fmt 后 `check`/`run` 输出逐位一致；③ fuzz 抽样（yoru-fuzz 既有语料）无 panic。
- **CLI**：`yoru fmt <path>`（原地）+ `--check`（CI 模式，输出 diff exit 1）。
- **风险**：换行终止语法（决策：换行终止）——**fmt 必须理解 newline 敏感文法**，AST 打印时自动消歧（行拼接歧义处插/去换行）。这是 F 线唯一硬骨头，首个 spike 先验证「AST→文本→同 AST」在换行敏感点成立。

### 2.2 注册表收尾（R）

- 立即可做（无新依赖）：`map.get(m, k)` / `map.get_or(m, k, d)`（27 号 §3.2，stdlib 增量 + Param DSL 注册 + 三处对账测试）。
- J 系按 23 号 §8 既有排期：J1 using（注入式 import，动 parser+typeck）、J3 const 求值、J4 SOA benchmark、J8 distinct 回写。
- 对账纪律：每次增删跑 `registry_dispatch_reconciled`（VM 全责实现断言）。

### 2.3 doctest（D）

> **2026-10-13 落地**（序 7 批次）。原始方案与实落的差异：① crate 形态 = 新 crate `yoru-doctest`（lib 提取+执行语义 + CLI `yoru doctest <path>...` 薄接线，V1 对拍测试同 crate 复用执行设施）；② 提取面增加 `.yoru` 源 `///` 文档注释内嵌块（spec 19.1 既定「/// = doctest 源」，决策 83 词法一等保留后零成本）——剥前缀后走同一围栏提取器，单一实现；③ `// error:` 断言 = error 级诊断码集合**精确**比对（写全防漂移，比原文「包含」更严）；④ 块形态约定 = 完整编译单元（VM `entry=None` 找 main），doc 块自包含不继承宿主声明；⑤ V1/V2 CI 化：V1 最小形态（examples 11 篇 typeck ok ⟺ lower ok 对拍）已随 `yoru-doctest` tests 落地，V2 语法驱动语料生成仍顺延（30 号 §6）。

- **提取**：markdown 围栏 ```yoru 块 + 尾注 `// => 期望输出`（或 `// error: Y-T0002` 断言诊断码）。
- **执行**：编译为模块 → run → `take_output()` 与期望逐位比对；`check` 类块只验诊断码集合。
- **范围**：设计文档 01/06/19 号内嵌示例 + examples/math README 运行契约；CI job（既有 ci.yml 增 doctest 步）。
- **价值**：C8 规格漂移的机械化防线——文档示例坏了 CI 红，而非 26 号式事后人工登记。

### 2.4 LSP（L）

- **服务器形态**：独立 crate `yoru-lsp`（stdio JSON-RPC）；协议库裁决（tower-lsp vs 手写最小子集）在开工时按当时生态状态定，先做诊断 + format（复用 F）+ hover 三动作即可用。
- **诊断桥**：typeck JSON 结构化诊断（决策 7）→ LSP Diagnostic 一对一映射（span→range 换算 UTF-16）。
- **补全数据源**：内建注册表（23 号 T2 面自文档化，Param doc 字段现成）+ 局部作用域变量——注册表 doc 字段是 hover/补全的免费内容源。
- **前置**：F 线完成（format 动作）+ R 线注册表稳定。
