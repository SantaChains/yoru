# 10 抗冲击测试体系（SQLite 精神）

[上一章：09 学习借鉴](09-学习借鉴.md) | [目录](README.md) | [下一章：11 决策记录](11-决策记录.md)

## 10.1 SQLite 测试方法论（事实核实，官方 testing.html/TH3 文档）

- 四套独立测试框架：TCL 开发测试（51445 用例）、TH3（约 240 万参数化测试，100% 分支覆盖率+100% MC/DC，航空标准 DO-178B）、SQL Logic Test（720 万查询，与 PostgreSQL/MySQL/SQL Server/Oracle 差分对比）、dbsqlfuzz（libFuzzer+自定义 mutator，同时变异 SQL 与数据库文件，336 种子文件，约 5 亿变异/天）。
- 规模：约 15.6 万行源码 vs 约 9200 万行测试代码，测试比约 590:1。
- 异常测试：OOM 注入（替换 malloc，迭代推进失败点，fail-once/fail-continuous 两模式）、I/O 错误注入（自定义 VFS）、崩溃测试（子进程随机崩溃+VFS 随机重排未同步写，事后 integrity_check 验证）、复合失败（恢复过程中再失败）。
- 变异测试：编译到汇编逐条翻转分支指令，验证测试能否捕获，统计 survivors。
- 防御宏：ALWAYS()/NEVER()（测试模式断言、覆盖模式常量、发布模式直通）；testcase() 强制边界值与布尔向量测试（源码 1184 处）。
- 元测试：gcov 覆盖运行验证测试质量，再用交付配置重跑验证两次输出一致（发现 UB 与编译器 bug）。
- 快速回归：veryquick 30.4 万用例数分钟内跑完；全量发布 44 次构建 1.98 亿测试约 7 小时（3 核）。
- 发布纪律：约 200 项人工检查清单、至少 3 天多平台测试、每次提交跑快速回归。
- 效果引述：达到 100% MC/DC 后 Android 平台停止收到 bug 报告（Richard Hipp）。

## 10.2 对 Yoru 的测试体系映射（四套框架对应物）

1. 单元与集成测试（对应 TCL）：cargo test，按 lexer/parser/typechecker/VM 分层；每层正向/反向用例；每 bug 修复必须附带回归测试（硬性纪律）。
2. 全覆盖测试（对应 TH3）：核心编译器+VM 分支覆盖率门槛——阶段0 ≥90%，阶段3 目标 100% 分支+90% MC/DC；testcase() 等价物：边界值矩阵测试（INT64_MIN/MAX、NaN/Inf/-0.0、空串/1MB 串、深递归、大量闭包、嵌套 match）。
3. 差分测试（对应 SLT）：三引擎一致性——解释器/JIT/AOT 对同一程序输出必须一致（语言项目最强的正确性保证）；字节码反汇编输出与参考实现对比。阶段1 起步，阶段2 随 JIT 强化。
4. 模糊测试（对应 dbsqlfuzz）：四层 fuzz（lexer/parser/typechecker/VM），语法感知变异（关键：纯随机变异语义正确率仅约 4%——Squirrel/Griffin 实证，必须 AST 级类型感知变异才能到达深层逻辑）；种子语料库持续扩充。

## 10.3 异常测试（SQLite 最独特部分，直接移植）

- OOM 测试（P1）：Rust 侧分配计数注入，迭代推进失败点，fail-once/fail-continuous 两模式；验证 VM 每处分配失败路径优雅降级。
- 资源限制测试（阶段0 起）：执行超时强制中断、内存上限触发、栈深上限触发——验证 VM 优雅终止且不污染宿主。
- 崩溃/恢复测试（P1）：热重载中途强制中断；字节码损坏注入（随机翻转字节）+校验和失败路径（[04-执行引擎](04-执行引擎.md) 4.5 校验和强制）；宿主中断模拟。
- 复合失败（P2）：超时中断期间再触发 OOM；损坏注入后的恢复路径再失败。

## 10.4 变异测试与防御编码

- 变异测试（P2，限于核心路径）：翻转 VM 分支、替换运算符、删除边界检查、翻转跳转，统计 survivors。
- 防御宏等价物（阶段0 起）：debug_assert! 承载 VM 不变量（栈深、类型标签、闭包 cell 状态）；ALWAYS/NEVER 等价物以 debug_assert 区分"预期恒真/恒假"的防御条件。
- 元测试（阶段1）：release 与 debug 双配置跑同一测试，输出必须一致（发现 UB）。

## 10.5 浸透测试与内存安全

- 浸透测试（P1）：长时运行监控内存增长（引用计数泄漏检测——RC 泄漏是 Yoru 最大风险，soak 必须有）；热重载千次循环稳定性。
- 内存/UB 工具：Miri（Rust unsafe 检查，P1 起）、ASan/UBSan（宿主构建验证）。

## 10.6 发布门槛（每阶段退出标准之上叠加）

- 覆盖率达标（核心 ≥90% 分支，阶段3 目标 100% MC/DC）。
- fuzz 时长门槛（阶段0 起每发布 ≥24 小时四层 fuzz 无崩溃）。
- soak 时长门槛（阶段1 起 ≥48 小时无内存增长）。
- 三引擎一致性全绿（阶段2 起）。
- 跨平台矩阵（win/mac/linux/wasm，阶段1 起）。
- 性能基准无回归（fib、JSON 解析、math3d 热点，criterion 跟踪）。
- 每 bug 修复必须附回归测试，无例外。
