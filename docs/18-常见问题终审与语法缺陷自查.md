# 18 常见编程问题终审与语法缺陷自查（决策 44-55）

## 18.0 决策速览

| # | 决策 | 内容 | 依据 |
|---|---|---|---|
| 44 | 除法/取模语义 | 整数 `/` = **floor 除**，`%` = **floor-mod**（恒等式 `a == (a/b)*b + a%b`，除数为正时余数恒非负）；除零 = 运行时错误；`INT_MIN / -1` 等商溢出 = 运行时错误（与决策 29 同管网）；float 除零 = IEEE（Inf/NaN，不抛） | C/Java/JS/Go/Rust 全为截断余数、Python/Ruby 才是真模——跨语言移植在零边界翻车（分页/结算/循环缓冲实证）；floor-mod 使 `i % n` 恒为合法索引，**游戏环绕索引零成本**；计算账目案例：退款负数分摊错账；Java 抛/C++ UB 的 INT_MIN 陷阱在「溢出抛错」下自动闭合 |
| 45 | float 不进全序 | `Ord` 协议**不**为 float 实现（NaN 破坏全序）；`[float]` 排序用 stdlib `sort_floats`（内部 total_cmp，Rust 先验）；Map 键约束 Hash+Ord 自然排除 float 键 | 决策 30 的补全：总序协议遇 NaN 是经典类型系统漏洞；Rust `Ord for f64` 走 total_cmp 特例的教训——协议边界要干净 |
| 46 | rune 码点类型 | `for c in s` 产出 `rune`（码点，distinct int 内建等价，可显式 `as int`）；**禁 `s[i]` 下标**（码点索引是 O(n)，伪装 O(1)）；字符串访问只有迭代与切片（决策 33） | Swift 禁 String 下标同理由；决策 33「迭代按码点」需要码点一等类型承载，此前悬空 **【27 号 A4 已闭环，决策 81】**：实现曾拒绝 `rune as int`（Y-T0011）与本文矛盾——实测证实 lower CONVERT_RUNE / VM 码点域检查早已存在、仅 check_cast 单点漏列内建 Ty::Rune；已按 27 号 §5 方案①放宽（决策 81），本文承诺文字恢复有效。回归：`rune as int`→码点值、`int as rune`→域检查 fail-loud（char::from_u32） |

| 48 | 无默认/命名参数 | 函数**无默认参数、无命名参数**；参数列表即契约；可选配置走 struct 参数（`Config { ... }` 一形式） | 默认参数让签名撒谎（调用点看不到实际值）；命名参数与 struct 字面量字段双形式冲突；Python 默认参数可变对象陷阱是经典坑；Rust 无默认参数的实证 |
| 49 | 泛型类型 + 递归类型 | 泛型类型声明 `type Tree[T] = ...`（struct/tag 同形式，编译期单态化）；**递归类型允许**（值语义 + refcount 堆表示，递归点用 `T?`/box 终止，如 `Tree = Node(left: Tree?, val: int)`） | 树/链表不可声明则语言不可用；15 号只有泛型 fn 是硬缺口；refcount 堆使递归值类型无环即安全（禁环：typeck 不追踪环但运行时 drop 计数防泄漏——P2 明确环检测策略） |
| 50 | 顶层纯声明 | 顶层只有 `import`/`const`/`type`/`struct`/`tag`/`fn`，**无语句、无副作用**；顶层 `const` 仅限编译期可折叠表达式（字面量+算术+纯函数引用） | 顶层可执行语句破坏两遍编译（13 号名字解析前提）、模块加载顺序不确定性、热重载原子性；ML/Go/MoonBit 同纪律 |
| 51 | 源码卫生 | 标识符 = ASCII `[A-Za-z_][A-Za-z0-9_]*`；**词法器拒绝一切 Bidi 方向控制字符与零宽字符**（字符串/注释内也拒绝——错误而非警告） | **Trojan Source（CVE-2021-42574）**：Bidi 字符让审查者看到的代码与编译器执行的代码不同；Rust 1.56.1 起默认拒绝、GCC 12 加 `-Wbidi-chars`；研究者首推「语言规范明文禁止」——Yoru 从规范层免疫，lexer 一次检查零成本；同型异码字（homoglyph，CVE-2021-42694）被 ASCII 标识符一并根治 |
| 52 | 空集合字面量 | `let xs = []` 无上下文可推断时 typeck 报错，要求标注 `let xs: [int] = []`（错误消息附修复建议）；实参位置等有上下文处正常推断 | Rust 空Vec 同规则；空字面量是推断不可定的数学事实，不是实现缺陷 |

## 18.2 语法缺陷自查（对 15 号的修正）

以下为逐条审计 15 号后发现的缺陷——「语法看起来完整、语义或一致性有洞」：

### 缺陷 1：`struct` 与 record 双形式（违规修正 → 决策 53）

15 号同时有 `struct Entry { ... }`（名义）与 `type Vec3 = { x: float, ... }`（record 别名）——**两种声明数据形状的形式**，违反「一操作一形式」。且 struct 字面量 `Type { f: v }` 与 record 类型在 typeck 里的匹配规则会分叉。

> **决策 53：数据声明一律 `struct`（名义类型，协议 impl 挂靠点）；`type` 仅用于命名类型别名与 `distinct`。record 类型文法从 BNF 删除。**

### 缺陷 2：`try` 只传播 Result，Option 悬空（→ 决策 54）

错误四词承诺「`try`/`!`/`throw`/`match` 覆盖全部失败路径」，但 `try` 语义只定义了 Result 传播；函数返回 `Entry?` 时的「失败向上传播」没有形式，AI 只能手写 `if ... { return nil }`——失败词汇表出现缝。

> **决策 54：`try` 双传播——作用于 `Result<T, E>` 传播 Err、作用于 `T?` 传播 nil；typeck 校验宿主函数返回类型兼容被传播的失败型。一句话定义不变："try = 失败就向上返回"。**

### 缺陷 3：Map 索引与迭代形式未定（→ 决策 55）

`[K: V]` 类型有了（15 号），但「按键取值」和「遍历」无形式——这是集合 API 的最基本操作。

> **决策 55：Map 索引 `m[k]` 返回 `V?`（键不存在 = nil，而非抛错——「缺失」是常态不是异常，与 Option 语义同构）；Map 迭代 `for kv in m` 产出 entry（含 `.key`/`.value` 的 record，插入序见决策 36）。**

### 三条规则（无需新决策，直接入 15 号约束表）

1. **if 作表达式取值时必须带 `else`**（类型完整性，缺 else 的 if 是语句用法——两用但形式统一，if 表达式与语句本就同一形式）。
2. **`a..b` 区间语义全局唯一**：切片（决策 42）与 `for i in 0..n` 共用同一半开语义——一个记号一处语义，跨场景零特例。
3. **字面量 canonical 大小写**：hex 小写（`0xff`）、科学计数 `e` 小写——formatter（T3）强制，人写大小写均接受。

### 自查通过项（审计确认无缺陷）

值语义×闭包快照×智能收窄三者无循环依赖；`|>` 左线程与数据第一参数约定自洽；能力参数与泛型单态化正交；换行终止与 `${}` 插值无歧义（插值内换行禁止，收进 lexer 规则）；决策 26 严格 as 与决策 44 floor-div 组合后 int/float 完全隔离。
