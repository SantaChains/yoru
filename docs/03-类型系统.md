# 03 类型系统

[上一章：02 语法规范](02-语法规范.md) | [目录](README.md) | [下一章：04 执行引擎](04-执行引擎.md)

## 3.1 核心原则

1. 渐进类型：一致性关系 ~（Siek-Taha）为静态检查基础；无标注位置推断，推断失败降级为 dynamic。
2. 健全性分级：strict 追求"良类型程序不因类型错误出错"（soundness）；nonstrict 仅报告可证明的运行时错误（Luau 路线，消除误报优先）。
3. 空安全：无 null；缺省值用 Option<T>。Option 与 T 之间无隐式转换。
4. 无隐式类型转换：所有转换必须显式 `::` 或构造器。
5. 类型注解不改变运行时语义（渐进保证方向；边界检查由编译器插入，用户不可见）。
6. dynamic 是显式逃逸舱口：跳过静态检查，但进入静态上下文时受边界检查约束（区别于 TS 的 any 完全无约束）。

## 3.2 类型种类

- 原始：int（i64）、float（f64）、bool、string（UTF-8）、unit。
- 复合：struct（字段固定）、enum（ADT，可带载荷）、tuple（MVP 用 struct 别名表达）、list[T]、record（开放字典，仅用于动态互操作边界）。
- 函数类型：(T1, T2) -> R。
- 泛型：单参数简单泛型；禁止类型级计算、高阶类型、递归类型推断。
- 联合类型：T1 | T2（有限深度；语法子类型+擦除，语义子类型为未来方向）。
- Option<T>、Result<T, E>、dynamic。

## 3.3 类型关系

- 一致性 ~：dynamic ~ T（任意）；T ~ T；结构相同则一致。用于赋值与传参检查。
- 子类型 <:：MVP 结构子类型（Flow 风格）——struct A <: struct B 当且仅当 A 含 B 全部字段且类型一致；函数逆变参数、协变返回。名义类型为未来方向（AOT 优化需要）。
- 联合类型：子类型与一致性按成员分解。

## 3.4 模式（nonstrict / strict）

1. nonstrict（默认）：无标注变量推断为 dynamic；仅报告可证明的运行时错误；不检查未标注函数参数。适合快速脚本。
2. strict（文件头指令启用）：全量推断与检查；未标注函数参数按使用推断（局部推断方向）；返回与实参数量检查；可证明缺陷必须报错。
3. 两者共享同一推断与检查实现，仅错误抑制策略不同（Luau 错误抑制思路），避免维护两套类型系统。

## 3.5 边界检查策略（决策5，已确认）

- MVP：擦除型为主（TS 路线，零运行时开销）+ strict 全类型化时获得完整静态保证（无动态部分，健全无运行时代价）。
- 混合 typed/untyped 场景不做健全承诺，语义透明（通过模式声明）。
- 未来：transient 浅检查作为健全性升级方向（需 VM 类型标签）；guarded 不做（Takikawa 实测混合配置开销可超 10000%）。

## 3.6 核心类型规则

Γ ⊢ e : T 表示在环境 Γ 下表达式 e 具有类型 T。

- T-Var: x : T ∈ Γ ⟹ Γ ⊢ x : T
- T-Let: Γ ⊢ e : T 且 Γ, x : T ⊢ body : U ⟹ Γ ⊢ let x = e; body : U
- T-App: Γ ⊢ f : (A) -> B 且 Γ ⊢ a : A' 且 A' ~ A ⟹ Γ ⊢ f(a) : B
- T-If: Γ ⊢ c : bool 且 Γ ⊢ t : T 且 Γ ⊢ e : U 且 T ~ U ⟹ Γ ⊢ if c {t} else {e} : (T ⊔ U)
- T-Union: Γ ⊢ e : T ⟹ Γ ⊢ e : T | U
- T-Option: Γ ⊢ e : T ⟹ Γ ⊢ Some(e) : Option<T>；匹配 Some(x) 后 x : U（T ~ U）
- 健全性目标（strict 全类型化）：Progress + Preservation（正式证明为未来工作；MVP 以测试验证，见 [10-抗冲击测试体系](10-抗冲击测试体系.md)）。

完整规则集在实现阶段补全（[12-实现工作台](12-实现工作台.md) T0.3），以上为核心判定形式。

## 3.7 泛型限制

- 仅类型参数占位，无约束（无 trait/typeclass，MVP）。
- 泛型函数在调用点擦除（配合擦除型边界策略；单态化为 AOT 未来方向）。
- 递归泛型类型禁止（防类型推断不可判定，参考 Luau 对 System F 不可判定的处理）。

## 3.8 诊断约定（人+AI 双端）

Diagnostic 结构（与 [12-实现工作台](12-实现工作台.md) API 契约一致）：severity、message、span（源码位置）、suggestions（修复建议，P1）、json（结构化输出）。所有类型错误必须携带 span。
