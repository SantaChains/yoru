# 05 后端取舍与跨平台

[上一章：04 执行引擎](04-执行引擎.md) | [目录](README.md) | [下一章：06 标准库](06-标准库.md)

## 5.1 后端决策（方向已确认，实现分阶段）

MVP 不做 AOT/JIT。未来双后端（Kōdo 验证模式）：

| 后端 | 定位 | 依据（均已核实） |
|---|---|---|
| Cranelift（默认） | 嵌入一致、快速 AOT/JIT、沙盒代码生成 | Rust 原生；编译快约 10 倍；IR 无 UB；针对恶意输入硬化；支持 x86-64/aarch64/riscv64/s390x；约 20 万行（LLVM 约 2000 万）；Apache-2.0；代码质量约慢 LLVM 14% |
| LLVM（可选，inkwell crate） | 发布性能路径 | 最优代码质量、平台最广、PGO/LTO；代价：依赖与构建成本高 |

依据补充：Kōdo 双后端实测——LLVM 比 Cranelift 快 9-17%，编译时间增加为个位数百分比，codegen 只占流水线约 20%；Perry 案例教训——后端切换必须先完成热操作 inline lowering 并达到性能 parity，否则切换是灾难。

## 5.2 JIT（P2）

单层 JIT：字节码→CLIF→机器码，热点函数编译（Luau 可选 JIT 模式）。不做多层分级（V8 Ignition/TurboFan 复杂度教训）。热点计数模型、guard+snapshot 机制借鉴见 [09-学习借鉴](09-学习借鉴.md)。

## 5.3 跨平台

- VM 与编译器纯 Rust，零平台依赖；目标 Windows/macOS/Linux/Web（WASM）/移动。
- 数值语义跨平台一致：int=i64、float=f64 固定宽度；序列化显式 little-endian（[04-执行引擎](04-执行引擎.md) 字节码格式）。
- WASM 为未来验证项（解释器可编译到 WASM 在浏览器运行，宿主注入能力）。

## 5.4 IR 提升路径（未来）

栈式字节码 → 提升（flatten+SSA）→ CLIF（block params 而非 phi，Cranelift 风格）→ 机器码。MVP 不实现，但保持字节码稳定（[04-执行引擎](04-执行引擎.md) 4.8 版本纪律），使后续提升无需重写前端。
