## 1. 问题陈述

三问：
1. 主轴继续打磨语言本身，还是提升工具链？
2. 还有没有影响重大、奠定底层的问题缺陷未解决？
3. 取舍标准面向项目实际能力（单人+AI 协作、嵌入定位、AI 优先叙事）与长期收益。

## 2. 外部证据（四路调研）

### 2.1 工具链是语言承诺的一部分（gofmt → rustfmt → zig fmt 谱系）

- gofmt 案例研究（行业综述《The Slow March of Progress in Programming Language Tooling》）：**「gofmt 之前诞生的语言几乎不可能达到 Go 近 100% 的风格一致性」**——强默认格式化是「后来者语言」的结构性优势；Rust（rustfmt/clippy/cargo）与 Zig（zig fmt）主动拥抱这一课并获得 DX 优势。核心论断：「让开发者把工作做完的工具，是语言可用性的巨大组成部分；新语言有机会把最新工具创新烘焙进自身，而旧语言只剩多种矛盾做法或没有做法」。
- 对 Yoru 的含义：Yoru 是「后来者」，fmt/LSP/doctest 正是把 2010 年代工具创新烘焙进自身的窗口期——错过窗口，语言设计再好也无法兑现为可用性。

### 2.2 反面锚点：Odin 工具链击退真实用户

- 迁移纪实（Go → Odin → Zig，2026-02）：该开发者的评价是 Odin「语法上介于 Go 和 Zig 之间，看似完美的平衡，**却被糟糕的工具链打破——频繁崩溃的 LSP、不完善的文档以及诡异的编译器指令，最终将他推开了**」。Zig 胜出的决定因素是工具链成熟度（zig fmt/ZLS/交叉编译）而非语言能力。
- 对 Yoru 的含义：**语言设计不输 + 工具链差 = 用户流失**，有真实行为证据。Odin 语言设计本身备受好评（DOD、显式性），仍输在工具链。这直接否定「先打磨语言到完美再谈工具链」的路线。

### 2.3 性能是定位选择，不是绝对目标（QuickJS 四条铁律）

- QuickJS 源码级解析：其四条铁律（单文件/无 JIT/引用计数/无内联缓存）使热路径比 V8 慢 10-20×，但换来启动快 30×、内存小 20×、二进制小 40×——**性能差距是嵌入定位的自觉取舍**；嵌入场景（配置/编排/胶水脚本）中 QuickJS 自身就是「足够快」的公认基准。quickjs-ng 也是在项目成熟后才补 Shape/IC。
- 对 Yoru 的含义：6.5× 慢于 QuickJS（24 号实测坐标）**不阻塞嵌入叙事**——嵌入目标场景里 QuickJS 之上再慢 6.5× 仍属「解释器正常带宽」（对照：Duktape 比 QuickJS 再慢 5-10× 仍有大量生产使用）。P0a 廉价项（profile/LBC0 缓存/mimalloc）保持让位不撤档；P2+（快ening/Cranelift）在嵌入验证前是预测性投入，维持 25 号裁决。

### 2.4 AI 输出风格漂移 + formatter 吸收（AI 优先定位的核心组件）

- 行业实证：LLM 生成代码的风格漂移（命名/缩进/结构）是**采样物理决定的，temperature=0 也不可消除**；业界共识做法是「formatters absorb the formatting」——把一致性约束从概率模型（prompt）转移到确定性工具（程序化 formatter），后者保证 100% 合约一致。模型回退/多模型场景下漂移最烈，formatter 是唯一确定出口。
- 对 Yoru 的含义：Yoru 的差异化内核是「AI 优先语言」（14 号：编译快 > AI 错误少 > 热重载）。对 AI 优先语言而言，**fmt 不是 DX 奢侈品，而是定位自身的组件**：AI 写 Yoru → fmt 归一 → diff 干净 → doctest/CI 验证。F 线优先级因此获得定位级（而非体验级）辩护。

### 2.5 验证基建有现成低成本模板（差分测试不是自研科学）

- 同类项目实证（vibescript，Rust 解释器）：parser fuzz target（cargo-fuzz，PR 1 分钟 + nightly 1 小时）+ **checker 差分 harness（10 万程序：typeck 全检放行的程序 vs 保留类型检查的运行时对拍，已知分歧登记制）**——与 Yoru 需要的形态几乎一致，且 CI 化方案完整公开。
- cargo-fuzz 对 parse/lower 的战果：同类 Rust 语言教程项目（eldiro）**fuzz 约 1 秒即抓到 parser bug**。Rust 侧安全网（panic=不变量破坏）使 crash-fuzz 即高价值；差分 fuzz 补语义分歧类。
- 对 Yoru 的含义：D-17（if 表达式静默 nil）与 typeck 单点挡板三现之所以靠人工撞见，正是缺这道防线。**建设成本 ≈ 1-2 个批次，收益覆盖全部后续迭代**——这是所有候选项里「长期收益/成本比」最高的一项。

## 3. 判断：主轴转工具链，语言层只清 Critical 实现债

## 5. D-03 方向定夺：fail-fast（typeck 拒绝未实现协议的 struct 算术）

**裁决：方案② typeck fail-fast，否决方案①（lower 发协议方法调用）。**

影响面澄清：
- **改动面**：`check_arith` 对 struct 操作数不再查 `impls` 协议表放行，改发 Y-T 级诊断（明示「struct 算术随协议重载批次提供，当前用自由函数」）；单点改动，无 lower/VM 面。
- **理由 ①（消灭最危险类）**：现状是「合法构造 → 运行期崩溃」，且诊断 `Y-R9007` 不指向真实根因（算术 vs 协议缺口）——正是 26 号 §2.3 定义的「无报错/结果错」近亲。fail-fast 把错误从运行期提到编译期，与决策 74 panic-free 方向一致。
- **理由 ②（不建预测性管线）**：方案①（lower 发协议方法调用）需要 now 泛型分发/方法解析的最小雏形，而协议重载完整语义（含重载解析、运算符返回类型约束）属泛型批次——现在做方案①等于提前实现半个分发器，泛型批次落地时大概率返工。fail-fast 零返工面。
- **理由 ③（诚实原则）**：spec 19 的协议重载承诺在泛型批次兑现前，「typeck 放行」是对用户的虚假承诺；拒绝 + 明确诊断才是真实状态声明。
- **代价**：`impl Add` 声明在过渡期无算术效果（本就如此，typeck 只是停止假装支持）。协议 impl 语法保留，泛型批次激活时零语法变更。

## 6. V 线登记：语义差分测试基建（新增，插队 F2 之后）

- **定位**：与 D 线 doctest 互补不重叠——doctest 防**文档示例漂移**（C8），V 线防**编译器三层语义漂移**（typeck/lower/VM）。
- **触发证据**：typeck 单点挡板三现（rune as/Map 迭代/CONVERT_RUNE）、D-17 静默 nil 靠示例套件人工撞见、D-01/D-05 stale-rlib 复现漂移。
- **首步方案**（2.5 模板微缩）：
  1. **V0 crash-fuzz**：cargo-fuzz target = `parse → check → lower → run(有限步)` 全链，种子用 examples/ 11 篇 + 测试语料；验收 = panic 零命中（决策 74 panic-free 契约的机械化验证）。注意 libFuzzer 平台限制（Linux/macOS x86-64），CI 用条件 job（与 29 号 F0 边界注记一致），本地 Windows 以 nightly-ci 代跑。
     **✅ 2026-10-13 落地（crate `yoru-fuzz`）**：libFuzzer 不支持 Windows（官方确认）→ 自研确定性 harness（`fuzz_case(src, rng)` 即 future fuzz-target 函数，签名不变可薄包装）。五阶段 catch_unwind 全链（lex 变异生成含种子 tokenize → parse → typeck → lower → run 有限步=资源三限 `max_instructions 1e5/max_call_depth 64/max_heap 16MiB`，**零 VM 扩展**）；token 段级变异（字典 80+ 词：关键字全集+内建+运算符+字面量边界+注释四形态，Nowarp 实战：语法级变异是唯一稳定穿 parser 路径）+ rebuild 空白重排 + 深度守卫（MAX_NEST 48 防 parser 栈溢出 abort）；强度分布化（轻度变异为主，期望 ~1.5 轮）。`[profile.fuzz]`（release+overflow-checks+debug-assertions）。**验收：10 万 case 62s panic-free ✓**（~1600 case/s；覆盖 run 2.4%）；smoke 800 case 常驻 cargo test（三关键覆盖点断言 + 确定性重放）。**意外收获**：`reached typeck: 10`——10 例 typeck 通过但 lower 拒绝，typeck/lower 双面分歧实证（V1 对拍素材）。诚实边界：栈溢出 abort 类不可捕获（深度守卫+大栈缓解，CI 侧 ASan 兜底）；97% 止步 parse——深层覆盖优化属 V2 语料生成。
  2. **V1 差分**：同一程序语料在「typeck 全检放行」与「VM 保留运行期类型检查」两配置下对拍（Yoru 双模式渐进类型恰好免费提供两套检查器——这是设计红利），分歧即缺陷，已知分歧登记制。
  3. **V2 语料生成**：语法驱动的小程序生成器（基于 spec 19 产式），喂 V0/V1。
- **排期**：V0 插在 F2（fmt CLI）落地后、泛型批次前；V1/V2 随 D 线 CI 化同批。
